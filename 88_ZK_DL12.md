# Modern Generative Image Models: Diffusion, Flow Matching, Training, and the Frontier

Modern generative image modeling can be understood as the problem of transporting simple noise into structured visual data. Diffusion models solve this through stochastic denoising: a known forward process gradually corrupts clean images into Gaussian noise, and a learned reverse process removes that noise step by step. DDPM makes training practical with a closed-form way to sample any noisy timestep and a denoising objective that reduces to predicting the injected noise. DDIM keeps the trained denoiser but changes the sampling path, enabling deterministic and faster generation through timestep skipping.

Flow matching reframes generation as deterministic probability transport. Instead of learning a reverse diffusion chain, the model learns a time-dependent velocity field that moves samples from a noise distribution toward the data distribution. Conditional flow matching makes this efficient by training on simple interpolations between noise and data, turning the objective into supervised velocity regression. Rectified flow and reflow further straighten generation trajectories, reducing the number of solver steps needed at inference time.

Modern text-to-image systems combine these mathematical foundations with production training techniques. Pre-training builds broad visual knowledge, post-training improves aesthetics and prompt following, personalization adapts models to specific subjects or styles, and distillation reduces the number of sampling steps. Practical quality depends on timestep sampling, resolution-aware noise schedules, latent representations, semantic alignment losses, preference tuning, and prompt enhancement. Frontier systems increasingly use VAE latent spaces, Diffusion Transformer backbones, pretrained text encoders, and flow or rectified-flow objectives to balance quality, controllability, and inference cost. The same ideas are also expanding into video generation, agentic image editing, and diffusion-style text generation, where the central challenges become temporal consistency, precise edit control, long-context refinement, synthetic-data contamination, model collapse, and provenance.

## 1. Diffusion Models from First Principles: From Gaussian Noise to DDPM and DDIM

Diffusion models generate images by learning how to reverse a carefully designed corruption process. The model starts from Gaussian noise, then repeatedly predicts and removes noise until a clean image emerges. What makes this approach powerful is not just the sculpting intuition, but the fact that the forward corruption process is analytically tractable: because it is built from Gaussian transitions, we can derive a practical training objective and an efficient sampling procedure.

The main ideas behind diffusion models are five steps: why generation starts from noise, how the forward process is defined, how maximum likelihood becomes an ELBO, how the ELBO collapses into the DDPM noise-prediction loss, and how DDIM accelerates inference.

### The Basic Setup

The goal of generative modeling is to learn a model that can sample realistic images from an unknown data distribution $p_{\text{data}}(\mathbf{x}_0)$. Here, an image is treated as a vector $\mathbf{x} \in \mathbb{R}^n$, where $n = H \times W \times 3$ for an RGB image. A clean training image is denoted $\mathbf{x}_0$.

Diffusion models rely on two processes:

| Process                      | Name                | Direction      | Who defines it?     |
| ---------------------------- | ------------------- | -------------- | ------------------- |
| $q(x_t \mid x_{t-1})$        | **Forward process** | clean -> noisy | We define it        |
| $p_\theta(x_{t-1} \mid x_t)$ | **Reverse process** | noisy -> clean | The model learns it |

The reason generation starts from noise is practical and mathematical. Noise is easy to sample, it introduces diversity, and Gaussian distributions have closure properties that make the derivations tractable. The standard noise distribution is:

$$
\boldsymbol{\epsilon} \sim \mathcal{N}(\mathbf{0},\, \mathbf{I})
$$

The common simplification is to use isotropic Gaussian noise, where the covariance matrix is $\sigma^2 \mathbf{I}$. This means every dimension receives independent noise with equal variance. The data distribution itself is not assumed to be independent across pixels; only the injected noise uses this independence structure.

### The Forward Process

The forward process gradually corrupts a clean image. It is a Markov chain, meaning each noisy state depends only on the previous state:

$$
q(\mathbf{x}_t \mid \mathbf{x}_{t-1}, \mathbf{x}_{t-2}, \ldots, \mathbf{x}_0) = q(\mathbf{x}_t \mid \mathbf{x}_{t-1})
$$

The one-step transition is a variance-preserving Gaussian corruption:

$$
q(\mathbf{x}_t \mid \mathbf{x}_{t-1}) = \mathcal{N}\!\left(\sqrt{1 - \beta_t}\,\mathbf{x}_{t-1},\; \beta_t \mathbf{I}\right)
$$

Equivalently, using Gaussian reparametrization:

$$
\mathbf{x}_t = \sqrt{1 - \beta_t}\,\mathbf{x}_{t-1} + \sqrt{\beta_t}\,\boldsymbol{\epsilon}_t, \qquad \boldsymbol{\epsilon}_t \sim \mathcal{N}(\mathbf{0}, \mathbf{I})
$$

The parameter $\beta_t \in (0,1)$ controls how much noise is added at timestep $t$. The sequence $\{\beta_t\}_{t=1}^T$ is the noise schedule. In the original DDPM setup, $\beta_t$ increases gradually, so early steps add small amounts of noise while later steps destroy more structure.

The weights are chosen to preserve variance, so the signal and injected noise remain on a stable scale across timesteps.

It is convenient to define:

$$
\alpha_t \triangleq 1 - \beta_t
$$

Then the forward step becomes:

$$
\mathbf{x}_t = \sqrt{\alpha_t}\,\mathbf{x}_{t-1} + \sqrt{1-\alpha_t}\,\boldsymbol{\epsilon}_t
$$

This notation reveals the key telescoping property. Applying the same Gaussian-composition argument across many steps gives the central closed-form jump:

$$
\boxed{q(\mathbf{x}_t \mid \mathbf{x}_0) = \mathcal{N}\!\left(\sqrt{\bar{\alpha}_t}\,\mathbf{x}_0,\; (1 - \bar{\alpha}_t)\mathbf{I}\right)}
$$

Equivalently:

$$
\mathbf{x}_t = \sqrt{\bar{\alpha}_t}\,\mathbf{x}_0 + \sqrt{1 - \bar{\alpha}_t}\,\boldsymbol{\epsilon}, \qquad \boldsymbol{\epsilon} \sim \mathcal{N}(\mathbf{0}, \mathbf{I})
$$

where $\bar{\alpha}_t$ is the cumulative product:

$$
\bar{\alpha}_t \triangleq \prod_{i=1}^{t} \alpha_i = \prod_{i=1}^{t}(1 - \beta_i)
$$

This formula is the training workhorse. Instead of simulating $t$ forward corruption steps, we can sample any timestep $t$ and compute $\mathbf{x}_t$ directly in one step.

| $t$     | $\bar{\alpha}_t$           | $\mathbf{x}_t$ interpretation                                                                      |
| ------- | -------------------------- | -------------------------------------------------------------------------------------------------- |
| $t = 0$ | $\bar{\alpha}_0 = 1$       | $\mathbf{x}_0 = \mathbf{x}_0$ (clean image, no noise)                                              |
| $t = T$ | $\bar{\alpha}_T \approx 0$ | $\mathbf{x}_T \approx \boldsymbol{\epsilon} \sim \mathcal{N}(\mathbf{0}, \mathbf{I})$ (pure noise) |

The full forward process is therefore known analytically. That is the main trick: we design the corruption process so that its posterior quantities can be computed exactly during training.

### From Likelihood to ELBO

The model should assign high likelihood to clean training images:

$$
\hat{\theta} = \arg\max_\theta \log p_\theta(\mathbf{x}_0)
$$

The problem is that the clean image likelihood requires marginalizing over all possible noisy trajectories:

$$
p_\theta(\mathbf{x}_0) = \int p_\theta(\mathbf{x}_{0:T})\, d\mathbf{x}_{1:T}
$$

This integral is intractable for images because every $x_t$ is high-dimensional. DDPM resolves this by introducing the known forward process $q(x_{1:T} \mid x_0)$ as an importance distribution:

$$
\log p_\theta(\mathbf{x}_0) = \log \mathbb{E}_{q(\mathbf{x}_{1:T} \mid \mathbf{x}_0)}\!\left[\frac{p_\theta(\mathbf{x}_{0:T})}{q(\mathbf{x}_{1:T} \mid \mathbf{x}_0)}\right]
$$

Then Jensen's inequality turns the intractable log-likelihood into a lower bound:

$$
\log p_\theta(\mathbf{x}_0) \geq \mathbb{E}_{q(\mathbf{x}_{0:T})}\!\left[\log \frac{p_\theta(\mathbf{x}_{0:T})}{q(\mathbf{x}_{1:T} \mid \mathbf{x}_0)}\right] \triangleq \mathcal{L}_{\mathrm{ELBO}}
$$

The ELBO decomposes into reconstruction, prior-matching, and denoising-matching terms. The key measure is KL divergence:

$$
D_{\mathrm{KL}}(q \| p) = \mathbb{E}_{q}\!\left[\log \frac{q(\mathbf{x})}{p(\mathbf{x})}\right] = \int q(\mathbf{x}) \log \frac{q(\mathbf{x})}{p(\mathbf{x})}\, d\mathbf{x} \geq 0
$$

The ELBO decomposition is:

$$
\mathcal{L}_{\mathrm{ELBO}} = \underbrace{\mathbb{E}_q\!\left[\log p_\theta(\mathbf{x}_0 \mid \mathbf{x}_1)\right]}_{\text{reconstruction}} - \underbrace{D_{\mathrm{KL}}\!\left(q(\mathbf{x}_T \mid \mathbf{x}_0) \| p(\mathbf{x}_T)\right)}_{\text{prior matching}} - \sum_{t=2}^{T} \underbrace{D_{\mathrm{KL}}\!\left(q(\mathbf{x}_{t-1} \mid \mathbf{x}_t, \mathbf{x}_0) \| p_\theta(\mathbf{x}_{t-1} \mid \mathbf{x}_t)\right)}_{\mathcal{L}_{t-1}: \text{denoising matching}}
$$

For large $T$, the prior-matching term is almost free because $q(\mathbf{x}_T \mid \mathbf{x}_0)$ is designed to be close to $\mathcal{N}(\mathbf{0},\mathbf{I})$. The main training burden is therefore the denoising KL:

$$
\mathcal{L}_{\mathrm{ELBO}} \approx -\sum_{t=2}^{T} D_{\mathrm{KL}}\!\left(q(\mathbf{x}_{t-1} \mid \mathbf{x}_t, \mathbf{x}_0) \;\|\; p_\theta(\mathbf{x}_{t-1} \mid \mathbf{x}_t)\right) + \text{const}
$$

The true posterior inside this KL is tractable by Bayes' rule. In the diffusion setting:

$$
q(\mathbf{x}_{t-1} \mid \mathbf{x}_t, \mathbf{x}_0) = \frac{q(\mathbf{x}_t \mid \mathbf{x}_{t-1}) \cdot q(\mathbf{x}_{t-1} \mid \mathbf{x}_0)}{q(\mathbf{x}_t \mid \mathbf{x}_0)} \propto q(\mathbf{x}_t \mid \mathbf{x}_{t-1}) \cdot q(\mathbf{x}_{t-1} \mid \mathbf{x}_0)
$$

The posterior is Gaussian with mean:

$$
\tilde{\boldsymbol{\mu}}_t(\mathbf{x}_t, \mathbf{x}_0) = \frac{\sqrt{\bar{\alpha}_{t-1}}\,\beta_t}{1 - \bar{\alpha}_t}\,\mathbf{x}_0 + \frac{\sqrt{\alpha_t}(1-\bar{\alpha}_{t-1})}{1-\bar{\alpha}_t}\,\mathbf{x}_t
$$

and variance $\tilde{\beta}_t I$ where

```math
\tilde{\beta}_t = \frac{(1-\bar{\alpha}_{t-1})\beta_t}{1-\bar{\alpha}_t}
```

This matters because at training time we know $\mathbf{x}_0$, so we can compute the true posterior. At inference time we do not know $\mathbf{x}_0$, so the learned reverse model must approximate this posterior from $\mathbf{x}_t$ alone.

### The DDPM Training Objective

The denoising KL becomes simple because both distributions are Gaussians. When two multivariate Gaussians have the same fixed covariance:

$$
D_{\mathrm{KL}}\!\left(\mathcal{N}(\boldsymbol{\mu}_1, \sigma^2\mathbf{I}) \;\|\; \mathcal{N}(\boldsymbol{\mu}_2, \sigma^2\mathbf{I})\right) = \frac{1}{2\sigma^2}\|\boldsymbol{\mu}_1 - \boldsymbol{\mu}_2\|^2
$$

Thus, the denoising KL reduces to a squared distance between means:

$$
\mathcal{L}_{t-1} \propto \|\tilde{\boldsymbol{\mu}}_t(\mathbf{x}_t, \mathbf{x}_0) - \boldsymbol{\mu}_\theta(\mathbf{x}_t, t)\|^2
$$

The reverse model is assumed to be Gaussian:

$$
p_\theta(\mathbf{x}_{t-1} \mid \mathbf{x}_t) = \mathcal{N}(\boldsymbol{\mu}_\theta(\mathbf{x}_t, t),\, \sigma_t^2 \mathbf{I})
$$

Instead of predicting the posterior mean directly, DDPM parameterizes the mean through a noise predictor $\boldsymbol{\epsilon}_\theta$. After substitution, posterior-mean matching becomes noise prediction:

$$
\mathcal{L}_{t-1} \propto \mathbb{E}_{t,\,\mathbf{x}_0,\,\boldsymbol{\epsilon}}\!\left[\left\|\boldsymbol{\epsilon} - \boldsymbol{\epsilon}_\theta(\mathbf{x}_t, t)\right\|^2\right]
$$

The final simplified DDPM loss is:

$$
\boxed{\mathcal{L}_{\mathrm{DDPM}} = \mathbb{E}_{t \sim \mathcal{U}[1,T],\; \mathbf{x}_0 \sim p_{\mathrm{data}},\; \boldsymbol{\epsilon} \sim \mathcal{N}(\mathbf{0},\mathbf{I})}\!\left[\left\|\boldsymbol{\epsilon} - \boldsymbol{\epsilon}_\theta\!\left(\underbrace{\sqrt{\bar{\alpha}_t}\,\mathbf{x}_0 + \sqrt{1-\bar{\alpha}_t}\,\boldsymbol{\epsilon}}_{\mathbf{x}_t},\; t\right)\right\|^2\right]}
$$

Theoretically, the ELBO derivation introduces timestep-dependent weights. In practice, DDPM uses uniform weighting, which empirically improves sample quality.

<details><summary>The complete training loop is:</summary>

```
repeat:
  1. x_0 ~ p_data                    # Sample a clean training image
  2. t ~ Uniform({1, ..., T})        # Sample a random noise level
  3. ε ~ N(0, I)                     # Sample random noise
  4. x_t = sqrt(ᾱ_t) * x_0 +        # Compute noisy image in ONE step
           sqrt(1 - ᾱ_t) * ε        #   (using the closed-form jump)
  5. L = || ε - ε_θ(x_t, t) ||²    # Compute loss: predicted vs. actual noise
  6. θ ← θ - η * ∇_θ L             # Gradient descent step
until converged
```

</details>

The important point is that training does not simulate the full forward chain. Each training example samples a clean image, a timestep, and a noise vector, then constructs $\mathbf{x}_t$ directly using the closed-form jump.

### DDPM Inference

Generation runs the learned reverse process from pure noise:

$$
\mathbf{x}_{t-1} = \frac{1}{\sqrt{\alpha_t}}\!\left(\mathbf{x}_t - \frac{1-\alpha_t}{\sqrt{1-\bar{\alpha}_t}}\,\boldsymbol{\epsilon}_\theta(\mathbf{x}_t, t)\right) + \sigma_t\,\mathbf{z}
$$

where $\mathbf{z} \sim \mathcal{N}(\mathbf{0}, \mathbf{I})$ for $t > 1$ and $\mathbf{z} = \mathbf{0}$ for $t = 1$.

<details><summary>The algorithm is:</summary>

```
x_T ~ N(0, I)                        # Sample pure noise to start from
for t = T, T-1, ..., 2, 1:
  z ~ N(0, I)  if t > 1  else z = 0  # Stochastic noise (off at final step)
  x_{t-1} = (1/sqrt(α_t)) *          # Compute denoised estimate
             (x_t - (1-α_t)/sqrt(1-ᾱ_t) * ε_θ(x_t, t))
           + σ_t * z                  # Add inference noise
return x_0                           # Final clean image
```

</details>

This is ancestral sampling: each state is sampled from the learned conditional distribution of the previous state. The drawback is cost. With $T=1000$ timesteps, inference requires 1000 sequential neural network evaluations.

### DDIM: Faster Sampling

DDIM addresses the DDPM inference bottleneck. The key observation is that the DDPM loss only depends on the same marginals as the closed-form forward process, not on the exact step-by-step Markov structure. Therefore, we can construct a different process with the same marginals but different inference behavior.

DDIM defines a generalized non-Markovian posterior whose parameter $\sigma_t$ controls stochasticity. When $\sigma_t = \tilde\beta_t^{1/2}$, the process recovers DDPM-like stochasticity. When $\sigma_t = 0$, the update becomes deterministic.

At inference time, the unknown $\mathbf{x}_0$ is replaced by the model's clean-image estimate:

$$
\hat{\mathbf{x}}_0(\mathbf{x}_t, t) \triangleq \frac{\mathbf{x}_t - \sqrt{1-\bar\alpha_t}\,\boldsymbol\epsilon_\theta(\mathbf{x}_t, t)}{\sqrt{\bar\alpha_t}}
$$

Setting $\sigma_t = 0$ gives deterministic DDIM:

$$
\boxed{\mathbf{x}_{t-1} = \sqrt{\bar\alpha_{t-1}}\,\hat{\mathbf{x}}_0(\mathbf{x}_t,t) + \sqrt{1-\bar\alpha_{t-1}}\cdot\boldsymbol\epsilon_\theta(\mathbf{x}_t, t)}
$$

Now the next state is a pure function of the current state and timestep. The only source of randomness is the initial sample $\mathbf{x}_T \sim \mathcal{N}(\mathbf{0},\mathbf{I})$. This deterministic structure makes step skipping much more stable.

Instead of using every timestep $\{1,2,\ldots,T\}$, DDIM uses a subsequence $\tau = \{\tau_1 < \tau_2 < \ldots < \tau_S\}$. The DDIM update is applied between consecutive members of $\tau$:

$$
\mathbf{x}_{\tau_{i-1}} = \sqrt{\bar\alpha_{\tau_{i-1}}}\,\hat{\mathbf{x}}_0(\mathbf{x}_{\tau_i},\tau_i) + \sqrt{1-\bar\alpha_{\tau_{i-1}}}\cdot\boldsymbol\epsilon_\theta(\mathbf{x}_{\tau_i}, \tau_i)
$$

The effective speedup is roughly $T/S$. For example, reducing $T=1000$ to $S=50$ gives a $20\times$ speedup.

| Steps $S$ | Speedup $T/S$ | FID (relative)         |
| --------- | ------------- | ---------------------- |
| $T=1000$  | $1\times$     | Baseline (best)        |
| $S=100$   | $10\times$    | Slightly worse         |
| $S=50$    | $20\times$    | Acceptable             |
| $S=20$    | $50\times$    | Moderate degradation   |
| $S=10$    | $100\times$   | Noticeable degradation |

<details><summary>The DDIM step-skipping algorithm is:</summary>

```
# Inputs: trained model ε_θ, subsequence τ = [τ_S, τ_{S-1}, ..., τ_1],
#         stochasticity σ_t (set to 0 for deterministic DDIM)

x_τ_S ~ N(0, I)                        # Sample initial noise (the ONLY randomness)

for i = S, S-1, ..., 1:
  t  = τ_i                             # Current timestep
  t' = τ_{i-1}                         # Target timestep (less noisy)

  # Step 1: Predict noise
  ε_pred = ε_θ(x_t, t)                # One model forward pass

  # Step 2: Predict clean image from current x_t
  x0_pred = (x_t - sqrt(1 - ᾱ_t) * ε_pred) / sqrt(ᾱ_t)

  # Step 3: Re-encode to target level t'
  direction = sqrt(1 - ᾱ_{t'} - σ_t²) * ε_pred
  x_{t'} = sqrt(ᾱ_{t'}) * x0_pred + direction

  # Step 4: Add stochasticity (σ_t = 0 → deterministic DDIM)
  if σ_t > 0:
    z ~ N(0, I)
    x_{t'} += σ_t * z

return x_{τ_0} = x_0                   # Final clean image
```

</details>

DDIM reuses the same $\boldsymbol\epsilon_\theta$ trained with the DDPM loss. No retraining is required because the training objective depends only on the marginals, and DDIM preserves those marginals.

| Property                          | DDPM           | DDIM ($\sigma=0$)           |
| --------------------------------- | -------------- | --------------------------- |
| Steps needed                      | $T=1000$       | $S=10–50$                   |
| Stochastic at inference?          | Yes (per step) | No (only at $\mathbf{x}_T$) |
| Same $\mathbf{x}_T$ → same image? | No             | **Yes** (deterministic)     |
| Needs retraining?                 | —              | **No** (reuses DDPM model)  |
| Quality                           | Best           | Slightly degraded           |
| Speed                             | $1\times$      | $10–100\times faster$       |

There is also a useful continuous interpolation between DDPM and deterministic DDIM. Setting $\sigma_t = \eta \cdot \tilde\beta_t^{1/2}$ for $\eta \in [0,1]$ lets practitioners trade off diversity and determinism.

## 2. Flow Matching from First Principles: Deterministic Transport for Generative Modeling

Flow matching reframes image generation as a deterministic transportation problem. Instead of repeatedly adding and removing random noise, it asks a direct question: how can we move samples from an easy initial distribution, usually Gaussian noise, into the target data distribution along a continuous path?

The answer is to learn a time-dependent vector field. This vector field tells each point where to move and how fast to move at every moment between $t=0$ and $t=1$. Once learned, generation becomes the numerical integration of an ordinary differential equation rather than a stochastic denoising chain.

The core ideas behind flow matching: the shift from diffusion-style stochastic dynamics to deterministic probability transport, the link between particle trajectories and evolving densities, the conditional flow matching objective, the practical training and inference algorithms, and the role of rectified flow in fast generation.

### From Stochastic Diffusion to Deterministic Transport

Diffusion and score matching can be described using stochastic differential equations. An SDE combines deterministic drift with random Brownian motion:

$$
d\mathbf{x} = f(\mathbf{x}, t)dt + g(t)d\mathbf{w}
$$

Here, $f(\mathbf{x}, t)$ is the drift term, and $g(t)d\mathbf{w}$ is the stochastic diffusion term. Earlier diffusion-based approaches rely heavily on this stochastic term to describe noising and denoising processes.

Flow matching takes a different view. It removes the stochastic diffusion term from the center of the story and treats generation as probability transport. We begin with an initial distribution $p_0$, usually Gaussian noise, and want to end with a target distribution $p_1$, the clean data distribution.

This convention flips the timeline used in DDPM:

| Framework            | $t=0$       | Final time |
| -------------------- | ----------- | ---------- |
| DDPM-style diffusion | Clean data  | Noise      |
| Flow matching        | Noise $p_0$ | Data $p_1$ |

The path of a single sample is written as $\mathbf{x}_t$. The flow function maps an initial point to its location at time $t$:

$$
\psi_t(\mathbf{x}_0) = \mathbf{x}_t
$$

At the distribution level, $p_t(\mathbf{x})$ denotes the probability path between $p_0$ and $p_1$. The central object flow matching learns is the vector field $u_t(\mathbf{x})$.

For every position $\mathbf{x}$ and time $t$, $u_t(\mathbf{x})$ gives a velocity. Unlike a score function, which points toward higher-density regions, a vector field gives direct movement instructions. If the vector field is correct, following it transports noise into data.

### The ODE View: Moving Individual Samples

At the level of a single particle, movement is governed by an ordinary differential equation:

$$
\frac{d\mathbf{x}_t}{dt} = u_t(\mathbf{x}_t)
$$

Solving this ODE gives the trajectory $\mathbf{x}_t$ and therefore the flow $\psi_t(\mathbf{x}_0)$. At inference time, this is exactly what a flow-matching sampler does: start from noise and integrate the learned vector field until $t=1$.

For deterministic generation to be well-defined, the vector field must be sufficiently regular. This ensures that trajectories do not branch randomly or cross in a way that destroys uniqueness. Given the same starting point $\mathbf{x}_0$, the ODE should produce one deterministic path.

### The Continuity Equation: Moving Distributions

The ODE describes individual samples. The corresponding distribution-level view is the continuity equation, a partial differential equation borrowed from fluid dynamics. It expresses conservation of probability mass: probability does not appear or disappear, it only moves.

To describe how much probability mass moves through a point, we use probability flux, which combines density and velocity. Velocity alone is not enough: fast movement in a region with almost no probability mass has little effect.

The continuity equation is:

$$
\frac{\partial p_t(\mathbf{x})}{\partial t} = -\nabla \cdot (p_t(\mathbf{x}) u_t(\mathbf{x}))
$$

The divergence operator $\nabla \cdot$ measures net outflow. If more mass leaves a small region than enters it, density decreases. If more mass enters than leaves, density increases.

This equation is the theoretical anchor of flow matching: if a vector field $u_t$ satisfies the continuity equation for a probability path $p_t$, then solving the ODE with $u_t$ transports samples according to that path. The vector field generates the probability path.

This also explains why older continuous normalizing flows were expensive. CNFs tried to maximize likelihood directly, which required simulating the ODE and tracking the divergence of the vector field during training. Backpropagating through an ODE solver is slow. Flow matching avoids that by replacing likelihood simulation with a direct regression objective.

### Conditional Flow Matching

The full problem is hard: learn a vector field that transports Gaussian noise to the entire data distribution. Flow matching simplifies it by first considering a conditional problem. Instead of mapping noise to all possible images, map noise to one specific data point $\mathbf{x}_1$.

The conditional probability path is:

$$
p_t(\mathbf{x} \mid \mathbf{x}_1) = \mathcal{N}(\mathbf{x};\; t\mathbf{x}_1,\; (1-t)^2\mathbf{I})
$$

At $t=0$, this is standard Gaussian noise. At $t=1$, the variance collapses to zero and the distribution becomes concentrated at the target data point $\mathbf{x}_1$.

This conditional path has a simple reparametrization:

$$
\mathbf{x}_t = t\mathbf{x}_1 + (1-t)\mathbf{x}_0, \quad \text{where } \mathbf{x}_0 \sim \mathcal{N}(\mathbf{0}, \mathbf{I})
$$

In words, $\mathbf{x}_t$ is a straight-line interpolation between initial noise $\mathbf{x}_0$ and target data $\mathbf{x}_1$.

Taking the time derivative gives the conditional vector field:

$$
u_t(\mathbf{x}_t \mid \mathbf{x}_1) = \mathbf{x}_1 - \mathbf{x}_0
$$

This is the key simplification. For the conditional path, the target velocity is just a constant displacement from the noise sample to the data sample.

The full marginal probability path can be recovered by averaging conditional paths over the data distribution. The marginal vector field is a weighted average of the conditional vector fields. Directly computing it is intractable because it requires integrating over the whole data distribution. The central result of conditional flow matching is that we do not need to compute it directly. Minimizing the conditional objective is equivalent, in expectation, to minimizing the intractable marginal flow matching objective.

The conditional flow matching loss is:

$$
\mathcal{L}_{\text{CFM}}(\theta) = \mathbb{E}_{t, q(\mathbf{x}_1), \mathbf{x}_0}\left[ \| u_\theta(\mathbf{x}_t, t) - (\mathbf{x}_1 - \mathbf{x}_0) \|^2 \right]
$$

Training therefore reduces to a simple supervised regression task. Sample a data point, sample noise, sample a time, construct the interpolated point, and train the model to predict the velocity $\mathbf{x}_1 - \mathbf{x}_0$.

The simplicity is slightly deceptive. Each conditional path is straight, but the learned marginal vector field need not be straight. In high-dimensional space, many conditional paths overlap and cross. The model learns an average velocity at each location, which can produce curved trajectories at inference time.

### Training Flow Matching

The training algorithm is simulation-free. There is no ODE solve inside the training loop.

<details><summary>In code:</summary>

```python
# 1. Sample data
x_0 = sample_noise()       # ~ N(0, I)
x_1 = sample_data()        # ~ p_data
t = sample_time()          # ~ U(0, 1)

# 2. Construct intermediate point
x_t = t * x_1 + (1 - t) * x_0

# 3. Predict velocity
predicted_velocity = model(x_t, t)

# 4. Compute loss
target_velocity = x_1 - x_0
loss = MSE(predicted_velocity, target_velocity)

# 5. Backpropagate
loss.backward()
optimizer.step()
```

</details>

This exactly implements the conditional flow matching loss. The network sees noisy intermediate points $\mathbf{x}_t$ and learns the velocity that would move them toward data.

This is also why existing diffusion architectures can be reused. A U-Net or diffusion transformer can take an image-like tensor and a time embedding, but instead of predicting noise or a score, it predicts velocity.

### Inference with an ODE Solver

At inference time, generation starts from Gaussian noise and numerically solves the learned ODE. The simplest solver is Euler's method:

$$
\mathbf{x}_{t+\Delta t} = \mathbf{x}_t + u_\theta(\mathbf{x}_t, t)\Delta t
$$

<details><summary>In code:</summary>

```python
x = sample_noise()         # x_0 ~ N(0, I)
dt = 1.0 / num_steps

for i in range(num_steps):
    t = i * dt
    velocity = model(x, t)
    x = x + velocity * dt  # Euler integration step

return x                   # This is x_1 ~ p_data
```

</details>

Unlike diffusion sampling, no new stochastic noise is injected during generation. The randomness comes from the initial noise sample. Given the same initial $\mathbf{x}_0$ and the same deterministic solver, the output is deterministic.

Because this is an ODE rather than an SDE, solvers can often take larger steps than stochastic samplers. The main limitation is trajectory curvature: if the learned path bends sharply, the solver needs smaller steps to track it accurately.

### Rectified Flow and Reflow

Flow matching trains on straight conditional paths, but the learned marginal trajectories can still curve because many conditional paths overlap. Curved paths are expensive: a numerical solver must take enough steps to follow the changing direction of the vector field.

Rectified flow addresses this by straightening trajectories. The procedure, often called reflow, works as follows:

1. Train an initial flow-matching model.
2. Use it to transport noise samples $\mathbf{x}_0$ into generated samples $\hat{\mathbf{x}}_1$.
3. Treat each pair $(\mathbf{x}_0, \hat{\mathbf{x}}_1)$ as a coupled pair.
4. Train a new model to move between these coupled points along straight lines.

The reflow target velocity is the displacement $\hat{\mathbf{x}}_1 - \mathbf{x}_0$. The reason this helps is that the second model no longer pairs arbitrary noise with arbitrary data. It pairs each noise sample with the output that the first model already maps it to. These coupled pairs cross less often, so the new trajectories become straighter.

If a trajectory were perfectly straight, Euler's method could move from $t=0$ to $t=1$ in one large step. In practice, rectified flow can reduce the number of inference steps dramatically, sometimes to only a few steps.

Reflow is not free. Generating the coupled pairs requires running the current model, and numerical solver errors or model approximation errors can accumulate. Repeating reflow too many times can degrade quality, so one or two rounds are usually the useful range.

### Relationship to Diffusion and Score Matching

Flow matching, diffusion, and score matching are not unrelated families. They are different views of the same broader problem: constructing a path between a simple noise distribution and a complex data distribution.

The stochastic interpolants framework makes this relationship explicit. Across these methods, the core quantities are noise, score, and velocity. Given two of them, the third can often be derived mathematically.

The practical differences are in the training target and sampler:

| Method         | Central object                                  | Typical sampler               | Training target    |
| -------------- | ----------------------------------------------- | ----------------------------- | ------------------ |
| DDPM           | Noise prediction                                | Reverse denoising chain       | Added noise        |
| Score matching | Score $\nabla_{\mathbf{x}}\log p_t(\mathbf{x})$ | SDE or Langevin-style sampler | Score field        |
| Flow matching  | Velocity $u_t(\mathbf{x})$                      | ODE solver                    | Transport velocity |

This unification explains why flow matching can use architectures originally developed for diffusion. The modeling interface is similar; the loss function and interpretation change.

## 3. Training Modern Image Generation Models: From Pre-Training to Distillation

Training a modern text-to-image model is not a single step. It is a lifecycle. A model first learns to generate images from massive data, then learns to generate better and more aligned images, then gets personalized for specific use cases, and finally gets compressed into a faster sampler for production.

There are five connected ideas: the modern flow-matching training objective, practical timestep sampling and resolution tricks, representation alignment for faster pre-training, post-training methods for quality and preference alignment, DreamBooth and LoRA for personalization, and distillation methods that reduce generation from hundreds or thousands of steps to only a few.

### The Training Lifecycle

Modern text-to-image training can be organized into four stages:

1. **Pre-training** teaches the model to generate basic images from scratch using massive datasets and compute.
2. **Post-training** teaches the model to generate good images: aesthetically pleasing, prompt-following, and aligned with human preferences.
3. **Tuning** personalizes the model for specific users, subjects, or niche tasks.
4. **Distillation** makes the model fast enough for production by reducing the number of required generation steps.

Earlier image-generation systems often used DDPM-style diffusion or score-matching objectives. Modern systems increasingly favor the flow matching paradigm because it gives a simple and effective training target: predict the vector field that moves noise into data. In the simplest setup, the model is penalized when its predicted velocity differs from the straight-line direction $\mathbf{x}_1 - \mathbf{x}_0$, with $\mathbf{x}_t$ built as an interpolation between initial noise and clean data.

The goal is not just to fit this loss, but to make every training iteration useful. That is where timestep sampling becomes important.

### Sampling the Right Timesteps

Not all timesteps are equally hard.

At $t \approx 0$, the input is almost pure noise. The model has little image structure to reason about and can often predict something close to an average direction. At $t \approx 1$, the image is almost clean, so the model mainly performs small local refinements. The hardest region is the middle, around $t \approx 0.5$, where the model must make structural and semantic decisions: pose, shape, composition, and object identity.

Uniform timestep sampling wastes many updates on easier regions. A better strategy is to concentrate training around the middle using logit-normal timestep sampling.

The normal variable $x$ lives on the full real line. Applying the sigmoid maps it into $[0,1]$. When $\mu = 0$, the resulting $t$ values concentrate near the middle, giving more training weight to the most difficult denoising and transport decisions.

<details><summary>A simple implementation looks like this:</summary>

```python
# Old way: Uniform sampling
# t = torch.rand(batch_size)

# New way: Logit-Normal sampling
# Concentrates samples around t=0.5
x = torch.randn(batch_size) * sigma + mu
t = torch.sigmoid(x)

# Construct noisy image
x_t = t * x_1 + (1 - t) * x_0
```

</details>

This is a compute allocation trick. The loss is still flow matching, but the model spends fewer updates on easy endpoints and more updates where image structure emerges.

### Resolution-Based Noise Shifting

Multi-resolution training introduces another subtle issue: the same mathematical noise level does not always create the same perceived difficulty.

High-resolution images contain more spatial redundancy. Neighboring pixels tend to be correlated, so the model can average information across nearby regions. As a result, a high-resolution image can feel less corrupted than a low-resolution image at the same nominal noise level.

Uncertainty grows as the noise ratio $\frac{t}{1-t}$ increases, but shrinks with $\sqrt{N}$, where $N$ is the number of pixels. Higher resolution gives the model more correlated evidence.

The practical implication is direct: when training on higher-resolution images, the schedule should shift toward more mathematical noise so the perceived task difficulty remains comparable across resolutions.

This bridges two views of noise. Mathematically, Gaussian noise is defined per dimension. Perceptually, the strength of that noise depends on image structure, redundancy, and resolution.

### Representation Alignment and Pre-Training

Pre-training asks one model to learn two things at once: low-level denoising dynamics and high-level semantic understanding. Representation Alignment, or REPA, accelerates this process by giving the model semantic guidance from an already-trained vision encoder such as DINOv2 or CLIP.

REPA adds an auxiliary loss. The main flow matching loss still teaches the model to generate the right image, while the auxiliary loss forces intermediate DiT representations to align with semantic teacher representations.

The conceptual REPA loss is:

$$
\mathcal{L}_{\text{REPA}} = \| \text{Proj}(\mathbf{h}_t^{(n)}) - \mathbf{E}_{\text{teacher}}(\mathbf{x}_1^{(n)}) \|^2
$$

Here, $h_t^{(n)}$ is the DiT hidden state for patch $n$ at noise level $t$, $\text{Proj}(\cdot)$ maps that hidden state into the teacher's embedding dimension, $E_{\text{teacher}}$ is the frozen pretrained encoder, and $x_1^{(n)}$ is the corresponding clean patch.

The point is to provide dense semantic supervision inside the model. Pixel-space flow loss tells the model how colors should move, but it does not directly explain that a region is a face, car, dog, object boundary, or scene element. REPA gives the internal layers a semantic target.

A notable observation from ablations is that applying REPA to earlier DiT layers can be more useful than applying it to later layers. Early layers help establish global semantic meaning, while later layers often specialize in local details and texture. A semantic teacher encoder is most helpful where global meaning is still being formed.

Pre-training also depends heavily on curriculum learning. Models often begin with easier data: lower resolution, fixed square aspect ratios, and simpler captions. Over time, the curriculum introduces harder examples: high resolution, variable aspect ratios, and longer descriptive prompts.

DiT architectures make this progression natural. An image is represented as a sequence of patches, so increasing resolution mainly increases sequence length, roughly $(H/P) \times (W/P)$ for image dimensions $H,W$ and patch size $P$. This is one reason transformers have become attractive for modern image generation: variable resolution and aspect ratio become sequence-length problems rather than major architectural redesigns.

### Post-Training for Quality and Alignment

After pre-training, a model can generate images, but those images may be average, poorly composed, or weakly aligned with the user's prompt. Post-training turns a capable base model into a useful product model.

There are several layers of post-training:

**Continued Training (CT)** expands knowledge. A general model can be trained further on a large domain-specific dataset, such as medical images, product imagery, or a particular visual domain.

**Supervised Fine-Tuning (SFT)** improves behavior. The model is trained on smaller, highly curated data so it learns higher-quality aesthetics: better lighting, composition, sharpness, style, and prompt adherence.

**Preference Tuning** teaches relative judgment. Instead of only showing the model good images, preference data shows which image is better than another. This helps correct persistent failure modes such as distorted anatomy, weak composition, or prompt mismatch.

Preference tuning often relies on reward models. Humans rate image pairs, and those labels train a reward model to score an image-prompt pair. The reward model can then support larger-scale alignment without requiring humans to manually score every generated sample.

Three important preference-tuning families are:

1. **Reward Feedback Learning (ReFL)** uses a differentiable reward model. Gradients flow from the reward score through the generated image and into the diffusion or flow model.
2. **Flow-GRPO** generates groups of images for the same prompt, scores them, and updates the model using relative advantage compared with the group average. A KL penalty helps prevent reward hacking or excessive drift.
3. **Diffusion-DPO** adapts direct preference optimization to diffusion or flow objectives, pushing the model toward preferred trajectories and away from rejected ones.

Conceptually, Diffusion-DPO pulls the model's predicted velocity toward the winning trajectory and pushes it away from the rejected trajectory.

This mirrors alignment methods from language models. The modality changes, but the optimization idea remains: learn from preferences, not just from raw examples.

### Prompt Enhancement

Post-training creates a practical user-experience issue. SFT data often contains long, detailed captions, while users usually write short prompts.

A model trained on captions such as "A warm, intimate indoor reading scene featuring a plush teddy bear seated beside a softly lit wooden table..." may not respond optimally to "a teddy bear reading." Prompt Enhancement solves this mismatch by using an LLM to expand a short user prompt into a richer descriptive prompt before sending it to the image model.

This is not a replacement for training. It is an interface layer that translates everyday user intent into the caption style the image model expects.

### Tuning with DreamBooth and LoRA

Tuning is about personalization. A general model can draw a dog, but a user may want it to draw their specific dog. A general model can draw a teddy bear, but a user may want one exact teddy bear in many contexts.

DreamBooth personalizes a diffusion model from a small set of subject images. The user provides a handful of photos, chooses a rare token such as `[V]`, and fine-tunes the model with prompts like "A `[V]` teddy bear." After tuning, the rare token binds to that specific subject, allowing prompts such as "A photo of `[V]` teddy bear in a snowy forest."

Naive DreamBooth causes catastrophic forgetting. If the model trains only on a few photos of one teddy bear, it may forget how to generate generic teddy bears or other concepts. Prior preservation loss mitigates this by mixing subject-specific images with generic class images, forcing the model to learn the new subject without erasing its prior knowledge.

Full fine-tuning is expensive, especially for models with billions of parameters. Low-Rank Adaptation, or LoRA, makes tuning practical by freezing the base model and learning only a small low-rank update:

$$
W_{\text{new}} = W_{\text{base}} + A \times B
$$

Here, $W_{\text{base}}$ is the original frozen weight matrix, $A$ has shape $d_{\text{out}} \times r$, $B$ has shape $r \times d_{\text{in}}$, and $r$ is a small rank hyperparameter with $r \ll \min(d_{\text{in}}, d_{\text{out}})$.

Instead of updating a huge matrix $W_{\text{base}}$, the model learns the product $A \times B$. If $W$ is $10{,}000 \times 10{,}000$, full tuning touches 100 million parameters. With $r=4$, LoRA trains only $10{,}000 \times 4 + 4 \times 10{,}000 = 80{,}000$ parameters.

Because the base model stays unchanged, LoRA adapters are portable. They can be saved separately, loaded dynamically, swapped, or combined with other adapters. This is why DreamBooth plus LoRA became a practical standard for subject and style personalization.

### Distillation for Fast Generation

The final lifecycle stage is distillation. In language models, distillation often means making the model smaller. In diffusion and flow models, the more urgent goal is usually step reduction: make the same model generate high-quality images in far fewer denoising or integration steps.

A full teacher model may require hundreds or thousands of steps. A production model may need 1 to 4 steps. Directly training a student to compress 1000 steps into one is usually too difficult, so several strategies have emerged.

#### Progressive Distillation

Progressive Distillation compresses the trajectory gradually: a 1000-step teacher trains a 500-step student, then the 500-step student becomes the teacher for a 250-step student, and the process repeats until the sampler is very short. The student does not immediately learn the whole trajectory. It first learns to replace two teacher steps with one student step, then repeats that compression.

#### InstaFlow and Perceptual Losses

InstaFlow combines trajectory straightening with distillation. If the generative path is straighter, a one-step student has an easier target. However, standard MSE can make images blurry because the student averages over uncertain high-frequency details.

To reduce blur, InstaFlow uses perceptual losses such as LPIPS. Instead of comparing raw pixels, LPIPS compares learned feature representations, making the loss more sensitive to perceptual similarity.

#### Consistency Models

Consistency Models enforce a different property: any two points on the same generation trajectory should map to the same final image. If this holds across the trajectory, the model can jump from an early noisy state directly to the final output.

The conceptual consistency loss is:

$$
\mathcal{L} = \| f_\theta(\mathbf{x}_t, t) - f_{\theta_{\text{EMA}}}(\mathbf{x}_{t+\Delta t}, t+\Delta t) \|^2
$$

Here, $f_\theta$ is the student model, $f_{\theta_{\text{EMA}}}$ is an EMA teacher, and $x_t$ and $x_{t+\Delta t}$ are nearby points on the same trajectory. The EMA teacher helps prevent collapse, such as predicting the same blank output for every input.

#### Distribution Matching and Adversarial Distillation

Trajectory-level MSE and perceptual losses are stable, but they can still produce softened outputs. Distribution Matching Distillation and Adversarial Diffusion Distillation move from matching individual trajectories to matching output distributions.

The objective is no longer only "make this student sample match this teacher sample." It becomes "make the distribution of student-generated images match the distribution of teacher-generated images." GAN-like adversarial objectives can produce crisper one-step outputs, but they are harder to train and more unstable.

This creates a real engineering trade-off:

| Method                               | Strength                           | Weakness                              |
| ------------------------------------ | ---------------------------------- | ------------------------------------- |
| Multi-step teacher                   | Highest quality                    | Slow and expensive                    |
| Progressive distillation             | Stable compression                 | Requires repeated training stages     |
| LPIPS / InstaFlow-style distillation | More perceptual sharpness than MSE | Quality can still drop                |
| Consistency models                   | Direct fast generation             | Requires careful anti-collapse design |
| Adversarial / distribution matching  | Crispest few-step outputs          | Training instability                  |

Modern systems usually perform these operations in latent space rather than raw pixel space. A VAE compresses images into a lower-dimensional representation, making teacher rollouts, student training, perceptual losses, and distribution matching far cheaper.

## 4. Trending Topics in Generative AI: From Flow Matching to Video, Editing, and Diffusion LLMs

After building up diffusion, score matching, flow matching, latent spaces, architectures, training, and evaluation, it asks a practical question: where is generative AI going next?

The answer is not a single model or technique. Modern image generation has become a modular system built from text encoders, compressed latent spaces, transformer backbones, training recipes, evaluation loops, and increasingly specialized inference procedures. At the same time, the field is expanding outward into video, agentic image editing, and even diffusion-style text generation.

Major trends: the move from stochastic diffusion to deterministic flow matching, the engineering realities of training and evaluation, the state of image models, the extension to video and editing, and the future outlook for diffusion beyond images.

### The Arc of Image Generation

Evolution through three major paradigms:

| Paradigm       | Core Idea                                               | Generation View                               |
| -------------- | ------------------------------------------------------- | --------------------------------------------- |
| Diffusion      | Add Gaussian noise forward, learn to remove it backward | Reverse a Markov corruption chain             |
| Score Matching | Learn the gradient of the log-density                   | Follow the score toward high-probability data |
| Flow Matching  | Learn a deterministic vector field                      | Transport probability mass through an ODE     |

Diffusion models begin with a clean image, gradually destroy it with Gaussian noise, and train a model to predict the noise needed to reverse that process. Score matching reframes the task as learning the score, the gradient of the log-probability density, which acts like a compass pointing toward the data distribution. Flow matching goes one step further: it treats generation as deterministic transport from a simple source distribution to the data distribution.

The stochastic differential equation view unifies diffusion and score-based models by describing sample motion as deterministic drift plus random perturbation. Flow matching removes the stochastic term and instead learns a velocity field. In this view, generation means solving an ordinary differential equation from a simple distribution to the data distribution. Flow matching, especially rectified flow, can produce straighter paths and fewer inference steps.

### Latent Spaces and Transformer Backbones

Modern image generators rarely operate directly on raw pixels. Pixel space is high-dimensional and highly redundant: nearby pixels are strongly correlated, and much of the raw representation is inefficient for learning. Variational Autoencoders (VAEs) solve this by compressing images into a lower-dimensional latent space.

This latent space provides two advantages. It reduces compute cost, and it gives the generative model a denser, more regular representation to learn. The trade-off is that a VAE is lossy: it can discard fine detail, introduce artifacts, and become a bottleneck for ultimate fidelity.

Architecturally, the field has also moved from U-Nets toward Diffusion Transformers (DiTs). U-Nets capture global structure through downsampling and preserve local details through skip connections. DiTs instead treat the latent representation as a sequence of patches and use self-attention to model long-range dependencies. This makes them more aligned with the scaling behavior that transformed language modeling.

The resulting modern image generator is modular:

| Component    | Role                                                    |
| ------------ | ------------------------------------------------------- |
| Text encoder | Converts prompts into conditioning embeddings           |
| VAE          | Compresses images into latent space and decodes outputs |
| DiT          | Learns the denoising or flow vector field               |
| Sampler      | Solves the reverse process or ODE efficiently           |

The field has moved from discrete Markov chains to continuous stochastic equations, and then toward deterministic transport. The broader trend is clear: models improve when the generative path becomes easier to learn and faster to sample.

### Training and Evaluation Are Engineering Problems

Once the mathematical paradigm is fixed, training quality depends heavily on practical engineering decisions. Two examples are logit-normal time sampling and resolution shifting.

Logit-normal sampling focuses training on intermediate noise levels. Very low noise states are almost clean and can be easy. Very high noise states may contain little usable signal. Mid-level noise states are often the hardest and most informative, so sampling more heavily from that region improves training efficiency.

Resolution shifting addresses a different issue. Higher-resolution images contain more redundant spatial correlation, so the same mathematical noise level can look less destructive to a human observer. To keep the task difficulty comparable across resolutions, the noise schedule must shift upward for higher-resolution data.

The training lifecycle then proceeds through several stages:

| Stage                                       | Purpose                                                      |
| ------------------------------------------- | ------------------------------------------------------------ |
| Pre-training                                | Learn broad visual and semantic knowledge                    |
| Continued training / supervised fine-tuning | Adapt to domains, styles, or quality targets                 |
| Personalization                             | Use methods such as DreamBooth or LoRA for specific subjects |
| Distillation                                | Reduce inference steps for production speed                  |

Evaluation is equally practical. Human preference remains central because image quality is subjective, but raw win rate is not enough. A model that only beats weak baselines can look better than it is. ELO-style evaluation corrects this by comparing actual outcomes against expected outcomes: if a lower-rated model beats a higher-rated model, the surprise is large and the rating changes substantially. If a strong model beats a weak one, the rating change is small. This makes ELO useful for leaderboards built from pairwise human comparisons.

Automated metrics still matter. FID measures distributional distance between generated and real images using deep feature statistics. Multimodal LLMs are also increasingly used as automated judges, accelerating iteration even when human evaluation remains the gold standard.

### The State of Image Models

State-of-the-art image models shows a mostly converged blueprint among leading open-weight systems:

| Design Choice  | Standard SOTA Pattern                    |
| -------------- | ---------------------------------------- |
| Loss           | Flow matching, especially rectified flow |
| Backbone       | Multimodal Diffusion Transformer         |
| Representation | VAE latent space                         |
| Conditioning   | Pre-trained text encoders                |

Models such as Flux 2 and Qwen Image, fit this stack closely. They validate the curriculum's main story: strong image generation combines latent compression, transformer scaling, learned conditioning, and flow-based generation.

The interesting exception is a model referred to as Hydra. Instead of using a VAE, this model operates directly in pixel space. Instead of relying on off-the-shelf text encoders, it trains text representations from scratch. To make pixel-space learning tractable, it uses very large image patches, such as $32 \times 32$, and compensates with enormous model scale, reaching up to hundreds of billions of parameters.

This illustrates a recurring tension in AI system design. A VAE is an elegant abstraction that makes learning easier, but it compresses away some information. Pixel-space learning removes that bottleneck but requires brute-force scale. The "Bitter Lesson": hand-engineered simplifications often lose to methods that learn directly from raw data once enough compute is available.

The deeper trend is toward end-to-end multimodal learning. If a system can learn image structure and text representations jointly, it may eventually bypass the modular pipeline of separate text encoder, VAE, and generator. The cost is much higher compute; the reward is potentially higher fidelity and fewer inherited bottlenecks.

### Video Generation as Space-Time Modeling

Video generation extends image generation by adding time. A video is a sequence of images, so the model must represent spatial structure and temporal continuity simultaneously. This increases cost sharply, but video also contains massive redundancy: consecutive frames are often very similar.

The standard response is a space-time latent representation. Instead of compressing only height and width, a video VAE compresses time as well. There is spatial-temporal compression expression:

$$
\text{Dimension} = \frac{1 + T}{4} \times \frac{H}{8} \times \frac{W}{8}
$$

Here, $T$ is the number of frames, $H$ and $W$ are spatial dimensions, $8$ is the spatial compression factor on each axis, and $4$ is the temporal compression factor. The "1 +" term preserves an anchor frame while compressing the remaining temporal sequence.

Video VAEs also introduce causality. A causal VAE uses convolutions that only look at the current and previous frames, not future frames. This avoids future leakage, supports streaming generation, and reduces memory pressure. The final frame of one generated chunk can become the anchor for the next chunk.

Inside the DiT, patches become 3D space-time blocks. Full self-attention across these blocks helps enforce temporal consistency: objects should not change identity, disappear, or gain and lose attributes across adjacent frames without cause.

The main lesson is that video generation is not merely image generation repeated many times. It requires a representation that understands continuity across time.

### Image Editing Becomes Agentic

A naive text-to-image editing model regenerates the whole image from scratch. This is risky: asking for a black-and-white conversion might produce a different image that happens to be black and white.

Agentic image editing reframes the problem. Instead of generating pixels directly, a vision-language model reads the image and the user request, infers the editing intent, and emits discrete commands for deterministic editing software. For example, it might output instructions such as increasing contrast, changing saturation, applying a mask, or adjusting a selected region.

This approach uses neural networks for semantic interpretation and classical tools for precise pixel manipulation. It is a more constrained and robust system design. The VLM decides what should be done; software such as Photoshop executes how it should be done.

Training such systems can involve reverse-engineering editing intent. Given an original image and a human-edited result, the model learns to infer the sequence of editing actions that likely produced the transformation. This shifts editing from unconstrained generation toward tool-using visual agents.

### Diffusion Comes Back to Text

One of the most interesting future directions is diffusion-style generation for language. Historically, vision borrowed from language: transformers, LoRA, preference optimization, and instruction-style conditioning all migrated into image generation. Now this describes the reverse movement: text generation borrowing diffusion ideas from vision.

Autoregressive LLMs generate one token at a time. This is simple and powerful, but it creates a sequential latency bottleneck. Generating $N$ tokens requires $O(N)$ dependent steps.

Diffusion text models instead start with a sequence of masked tokens and iteratively refine the entire sequence. Their time cost depends on the number of denoising steps rather than output length:

$$
\text{Autoregressive Time} = \mathcal{O}(N) \quad \text{vs.} \quad \text{Diffusion Time} = \mathcal{O}(T)
$$

Here, $N$ is the number of output tokens and $T$ is the number of diffusion steps. If $T$ is fixed, a diffusion text model can refine many tokens in parallel.

This is especially attractive for long outputs and code generation. Developers do not always write code left to right; they often fill in missing functions, patch middle sections, and revise structure globally. Diffusion-style text generation naturally supports fill-in-the-middle because the model attends to the whole sequence during refinement.

Variable-length generation remains a challenge, but block diffusion provides one approach: generate chunks iteratively until an end condition is reached. The broader idea is that text can be produced like a draft that improves over multiple passes, rather than as a single left-to-right stream.

### The Frontier: Cost, Data, Hardware, and Provenance

First, generation has an economic benchmark. The source notes a rough cost of about 10 cents per megapixel for a "perfect" generated image. Tracking this cost matters because image generation becomes more disruptive as quality rises and marginal cost falls.

Second, hardware remains a bottleneck. Transformers rely heavily on matrix multiplication, which drives demand for specialized accelerators and motivates research into analog hardware and other compute paradigms.

Third, the field faces a data-quality crisis. As AI-generated content fills the internet, future models risk training on outputs from earlier models. This can create model collapse: an echo chamber where artifacts and mistakes compound over generations of training data.

Fourth, provenance and safety become essential. Standards such as C2PA attach metadata to files, while watermarking systems such as SynthID hide imperceptible signals in generated media. These tools help identify synthetic content, support accountability, and may also help filter training data to reduce model collapse.
