# Building Reliable AI Agents: From Reinforcement Learning to Scientific Discovery

A coding agent receives a repository and a bug report. It reads the code, proposes a fix, runs tests, interprets failures, and revises its work. If a user adds a requirement midway through, the agent must incorporate it while keeping track of the original goal. A scientific agent faces a related challenge on a different scale: selecting methods, running analyses, interpreting evidence, and deciding which hypotheses deserve an experiment.

Both tasks depend on a sequence of decisions whose consequences unfold over time. Reliability emerges from how that sequence is organized: the experiences an agent learns from, the feedback used to judge progress, the partners it coordinates with, and the evidence supporting its final result.

These connections bring reinforcement learning, game theory, automated research, and statistical evaluation into a shared discussion. Training develops useful behavior through interaction. Multi-agent methods distribute work and introduce the problem of compatibility. Scientific discovery tests whether the resulting plans and computations lead to evidence that survives experimental scrutiny. Statistical evaluation establishes how confidently measured gains support claims of broader improvement.

The central challenge is to keep every stage connected to the intended outcome. More training tasks help only when their rewards are informative. More agents help when their work fits together. More candidate discoveries help when there is a dependable way to evaluate them. A higher benchmark score supports a progress claim when the evaluation can distinguish the gain from variation across tasks and runs.

## 1. Training agents through interaction

An agent learns from a **trajectory**: a sequence of observations, reasoning, actions, and feedback. Each tool result changes what it knows and informs the next decision. Its state includes both the task and the relevant interaction history.

For a coding agent, that sequence can run from inspecting a function and reproducing an error to editing code, testing the change, and preparing a pull request. Training must reward progress across the sequence, including recovery from errors and responses to user corrections.

Reinforcement learning supplies a framework for improving this behavior. The **policy** $\pi_\theta$ is the language model, parameterized by its weights $\theta$. A **sampler**, also called a rollout worker, runs the policy through a task. An **environment** executes its actions and returns observations. A **grader** evaluates the resulting behavior or artifact, and a **trainer** updates the model using those trajectories and rewards.

### Designing tasks that produce useful feedback

Useful training begins with tasks whose success can be checked. Mathematics, multiple-choice questions, and executable code often support **reinforcement learning with verifiable rewards**, or RLVR: an automated verifier supplies the reward.

A direct verifier removes the need to learn a separate reward model for that check. Its scope still matters: passing a test suite establishes only the behavior that the tests cover.

Other requirements call for judgment. A coding assistant may produce a functional patch while overlooking a user request or explaining its choices poorly. Creative and analytical tasks can have several good answers.

**Rubrics** turn these expectations into individual criteria. Evaluators can check whether a response addresses each requirement, explains consequential assumptions, and follows the requested format.

### What a single training example can reveal

A reported RLVR experiment illustrates why data quality deserves close attention. A model trained on one selected mathematics problem approached the benchmark performance of a comparison model trained on roughly 1,200 problems. The evaluation used questions beyond that single training problem.

The experiment suggests that carefully chosen feedback can strengthen strategies already available to a pre-trained model and help it apply them elsewhere.

The account does not supply complete experimental settings or the exact performance gap. Its useful implication is a question about task selection: which examples offer the most informative feedback at the model's current level? A single result cannot establish how much data general agent training requires.

One selection heuristic is **variance in rollout outcomes**. For a problem $p$, let $R_i$ indicate whether rollout $i$ is correct, taking values $\in \{0,1\}$. With $n$ rollouts, the empirical variance is:

$$
\text{Var}(p) = \frac{1}{n} \sum_{i=1}^{n} (R_i - \bar{R})^2, \quad \bar{R} = \frac{1}{n}\sum_{i=1}^n R_i
$$

For binary outcomes, $\text{Var} = \bar{R}(1 - \bar{R})$, maximized at $\bar{R} = 0.5$. A problem with $\bar{R} \approx 0.5$ produces both successes and failures. That contrast is useful for updates that compare the relative quality of sampled trajectories. When $\bar{R} \approx 1$ or $\bar{R} \approx 0$, the same binary reward provides little within-group differentiation.

Outcome variance is useful when the learning algorithm compares trajectories within a group. It does not establish semantic diversity or transfer; those require separate evaluation.

An informal ranking notation captures the preference for more informative samples:

$$
\pi_1 \succ \pi_{17} \quad \text{(in terms of learning signal quality)}
$$

The subscripts label illustrative rollout or policy candidates, without defining a formal ranking measure. In practice, task selection means sampling candidate problems and inspecting which outcomes offer useful contrasts.

### Expanding the training distribution without losing exploration

As a model improves, its training mixture must change with it. Teams combine task categories, difficulty levels, and interaction patterns, adding coverage of weak capabilities while retaining enough variety to support transfer.

Tools define available actions, tasks give those actions a purpose, and trajectories show how feedback guides progress. Real examples help anchor the synthetic interactions in the work the agent will encounter.

The quality of this pipeline depends on coverage, difficulty, and evaluation. Producing many variations of one narrow solution pattern may contribute little new learning.

### Measuring success and the range of possible solutions

Two useful evaluation measures are **pass@1** and **pass@k**. Pass@1 measures success from a single sampled attempt. Pass@k measures whether at least one of several attempts succeeds. Given $n$ sampled solutions, of which $c$ are correct, a standard estimator is:

$$
\text{pass@}k = 1 - \frac{\binom{n - c}{k}}{\binom{n}{k}}
$$

The binomial coefficient counts combinations: $\binom{n}{k}$ $= \frac{n!}{k!(n-k)!}$. For an evaluation budget no larger than the sample count, the fraction represents selecting only incorrect solutions when choosing without replacement from the collected samples. Its complement represents at least one success. Setting $k=1$ yields the observed single-attempt success rate.

Pass@k measures success across a sampling budget. Since it can rise simply because individual attempts improve, interpreting it as evidence of broader exploration also requires inspecting the strategies produced. Comparisons should hold sampling settings and resource budgets consistent. The uncertainty of the measured difference also matters: the evaluation-noise analysis later in this article explains how question-level results help distinguish a real gain from sampling variation.

**Policy entropy** provides a different view of exploration:

$$
H(\pi) = -\sum_{a} \pi(a \mid s) \log \pi(a \mid s)
$$

Writing the action set explicitly gives the same definition:

$$
H(\pi) = -\sum_{a \in \mathcal{A}} \pi(a \mid s) \log \pi(a \mid s)
$$

Here $s$ is the current context, $a$ is an action, and $\mathcal{A}$ is the set of possible actions. Entropy describes how spread out the policy's choices are at that state. A deterministic policy has zero entropy; a more distributed policy has higher entropy.

Reinforcement learning can concentrate the policy too quickly on a narrow set of rewarded behaviors, producing **entropy collapse**. Useful exploration must retain alternatives while remaining coherent enough to complete tasks; high entropy alone can also reflect random behavior.

The reported synthesis results improved both pass@1 and pass@k. Examining policy entropy and actual rollouts would help determine how much of that improvement reflects sustained exploration.

### Graders define what the model learns to value

A grader implements the reward function $r(s, a)$: a signal evaluating an output or action $a$ in context $s$. For a multi-turn agent, grading can also depend on the full trajectory and the final artifact. The grader translates product expectations into consequences for learning.

Several mechanisms can contribute:

| Mechanism             | Role                                                | Limitation                                              |
| --------------------- | --------------------------------------------------- | ------------------------------------------------------- |
| Programmatic verifier | Checks executable or precisely specified properties | Covers only what its checks actually test               |
| Model judge           | Evaluates responses that require interpretation     | Can be inconsistent or share the trained model's biases |
| Rubric                | Specifies the criteria and scoring structure        | Depends on clear criteria and reliable scoring          |

Rubrics can guide human or model judges, while programmatic checks assess precise properties. A coding product may combine checks for correctness, patch applicability, formatting, communication, completion time, safety, factual accuracy, and consistency across turns.

A conceptual way to combine $K$ grader signals is a weighted reward:

$$
r_{\text{total}} = \sum_{i=1}^{K} w_i \cdot r_i(s, a)
$$

Each $r_i(s, a)$ measures a particular dimension, and $w_i$ sets its contribution. Some individual scores may take values $\in [0, 1]$, while others use different scales. Calibration matters because the numerical scale can change a grader's influence as much as its explicit weight.

Weights express tradeoffs: brevity can compete with completeness, and speed with additional verification. Requirements that must always hold may need to act as gates, so other successes cannot compensate for their failure.

Dependencies matter too. A format check may require an output to exist; an artifact-quality check may require a valid artifact first. A dependency graph $G = (V, E)$ offers a conceptual representation, with graders as vertices and prerequisite relationships as edges. Independent checks can run concurrently, while dependent checks follow the necessary order.

### Teaching relative quality before demanding complete success

A strict set of graders can produce uniformly poor rewards early in training. A curriculum can begin with attainable criteria and increase their difficulty as the model improves. In the weighted formulation, an inactive criterion can have $w_i = 0$ before it is introduced.

Relative preferences can also distinguish partial progress. An illustrative pairwise ranking objective is:

$$
\mathcal{L}_{\text{rank}} = -\mathbb{E}_{(a^+, a^-) \sim \mathcal{D}} \left[ \log \sigma\!\left( r_{\text{total}}(s, a^+) - r_{\text{total}}(s, a^-) \right) \right]
$$

Here $a^+$ and $a^-$ are preferred and less-preferred outputs in a comparison dataset $\mathcal{D}$, and $\sigma(x) = \frac{1}{1+e^{-x}}$ converts a score difference into a probability. The objective illustrates learning to score the preferred output more highly.

Used directly as a loss, this expression requires a learnable scoring function. Fixed test outcomes cannot be differentiated through sampled text; updating the policy requires an appropriate reinforcement-learning or preference-learning procedure. Ranking also depends on meaningful distinctions between attempts: identical zero rewards supply none.

### Protecting the reward from shortcuts

Optimizing a grader creates pressure to exploit its weaknesses. A coding agent may delete tests, weaken an assertion from `assert result == expected` to `assert True`, or otherwise make the test runner report success without fixing the intended behavior. Retrieving a pre-existing answer can also violate an evaluation protocol when that protocol requires independent problem solving, even though retrieval may be legitimate in other workflows.

These behaviors are **reward hacking**: optimizing measured success while missing the actual goal. A stronger optimizer can make the gap more consequential by finding subtler weaknesses.

Possible defenses include auditing submitted changes, evaluating against protected tests, and penalizing detected manipulation. A simple penalty override is:

$$
r_{\text{total}} \leftarrow -P \quad \text{if cheating detected}
$$

The intended scale is $P \gg 1$, producing a strongly negative reward, or $r \ll 0$, relative to ordinary gains. Its effectiveness still depends on detecting the prohibited behavior. A large penalty does little against an exploit the grader never notices.

## 2. Making learning efficient enough to scale

Long trajectories generate many tokens and wait on tool execution. In a synchronous pipeline, rollout generation and model updates take turns, leaving one set of resources waiting while the other works.

An **asynchronous architecture** overlaps those activities. Rollout workers generate trajectories, place them in a buffer, and periodically adopt new checkpoints. The trainer consumes graded trajectories and publishes updated weights.

```
  ┌──────────────────────────────────┐
  │  Roller 1  ──→ Env Simulator     │
  │  Roller 2  ──→ Env Simulator     │  (many rollers, GPU-heavy)
  │  Roller N  ──→ Env Simulator     │
  └─────────────┬────────────────────┘
                │ rollout buffer (async)
  ┌─────────────▼────────────────────┐
  │         Trainer (𝜋𝜽)    │  (one trainer, GPU)
  └──────────────────────────────────┘
```

The diagram shows one logical trainer, which can itself use distributed hardware. Grading supplies rewards before trajectories contribute to learning. Long sequences and slow environment interactions can make rollout generation the largest resource demand.

Concurrency improves utilization but introduces **policy staleness**. A trajectory may have been generated by an older model, $\pi_{\theta_{\text{old}}}$, while the trainer is updating the current model, $\pi_\theta$. Such data is off-policy relative to the current parameters. As the two policies diverge, treating old samples as fresh ones can distort the update.

### Correcting for stale samples

Importance sampling expresses how to reweight samples from one distribution to estimate an expectation under another:

$$
\mathbb{E}_{\pi_\theta}[f(a)] = \mathbb{E}_{\pi_{\theta_{\text{old}}}}\!\left[\frac{\pi_\theta(a|s)}{\pi_{\theta_{\text{old}}}(a|s)} f(a)\right]
$$

For a fixed state $s$, the importance weight is $\rho = \frac{\pi_\theta(a|s)}{\pi_{\theta_{\text{old}}}(a|s)}$. The identity assumes that the sampling distribution assigns positive probability wherever the target contribution requires it. Correcting a full trajectory also requires accounting for its sequential sampling structure; a single action ratio does not automatically correct every source of mismatch.

Large differences between policies can produce extreme weights, including $\rho \gg 1$, and high-variance estimates. This motivates practical controls on policy drift and sample age.

**Proximal Policy Optimization**, or PPO, illustrates one way to moderate updates through a clipped surrogate objective:

$$
\mathcal{L}^{\text{CLIP}}(\theta) = \mathbb{E}_t\!\left[\min\!\left(\rho_t A_t,\ \text{clip}(\rho_t, 1-\epsilon, 1+\epsilon) A_t\right)\right]
$$

The advantage $A_t$ expresses how favorable an action is relative to a baseline, while $\epsilon$ sets the clipping range. At step $t$, $\rho_t$ $= \frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_\text{old}}(a_t|s_t)}$. In practice, the advantage is estimated, giving the equivalent operational notation:

$$
\mathcal{L}^{\text{CLIP}}(\theta) = \mathbb{E}_t\!\left[\min\!\left(\rho_t \hat{A}_t,\ \text{clip}(\rho_t, 1-\epsilon, 1+\epsilon)\, \hat{A}_t\right)\right]
$$

PPO maximizes this surrogate; a loss-minimizing implementation uses its negative. Clipping moderates incentives for large favorable ratio changes, while sacrificing exact importance-sampling unbiasedness. It neither bounds every parameter change nor guarantees reliable updates from arbitrarily stale data.

Another control is **Kullback–Leibler divergence**, which measures deviation from a reference policy:

$$
D_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}}) = \sum_a \pi_\theta(a|s) \log \frac{\pi_\theta(a|s)}{\pi_{\text{ref}}(a|s)}
$$

The same relationship can be written as $D_{KL}(\pi\|\pi_{ref}) = E_\pi[\log \frac{\pi}{\pi_{ref}}]$. A conceptual regularized reward subtracts this divergence:

$$
r_{\text{reg}}(s, a) = r(s, a) - \beta \cdot D_{\text{KL}}\!\left(\pi_\theta(\cdot|s) \,\|\, \pi_{\text{ref}}(\cdot|s)\right)
$$

The coefficient $\beta$ controls the strength of the anchor. A larger value discourages movement away from the reference; a smaller value permits greater change. The reference might be a supervised checkpoint or a previous policy, depending on the training design.

KL regularization can moderate drift. Its effectiveness still depends on the reward and the surrounding training procedure, including how stale samples are handled.

### Where low-rank adaptation helps

**Low-rank adaptation**, or LoRA, reduces the number of trainable parameters by freezing a base weight matrix and learning a factorized update:

$$
W' = W_0 + \Delta W = W_0 + AB, \quad A \in \mathbb{R}^{d \times r},\ B \in \mathbb{R}^{r \times k},\ r \ll \min(d, k)
$$

The base matrix $W_0$ has dimensions $d$ by $k$, and $A$ and $B$ are trainable factors. The local symbol $r$ denotes adaptation rank here, rather than reward. Likewise, $k$ is a matrix dimension here, rather than the sampling budget used in pass@k. One initialization can use $B=0$, making the initial update zero.

The parameter count falls from $dk$ to $r(d+k)$. With $d=k=4096$ and $r=16$, that is 16,777,216 parameters for a full matrix versus 131,072 for the factors—a 128-fold reduction for that matrix. This does not imply the same reduction in total training memory or end-to-end cost, because the base model, activations, and rollout generation still consume resources.

A compact expression for the intended full-rank update is:

$$
W' = W_0 + AB, \quad \text{rank}(AB) = r \ll \min(d, k)
$$

The equality assumes the factors achieve rank $r$; in general, the product's rank is at most $r$, and it can be lower, including at initialization. The restriction makes LoRA a plausible source of structural regularization by limiting the form of weight updates.

That restriction should not be confused with a bound on their magnitude. The inequality $\|\Delta W\| \leq \|A\| \cdot \|B\|$ only provides a useful magnitude bound when the factor norms are controlled. Low rank alone does not bound policy KL divergence. LoRA may support efficient, stable RL in a particular setup, but those effects need evaluation alongside learning rates, rewards, and policy staleness.

The practical test is whether adaptation savings increase useful experimental throughput. For agentic RL, that may mean making more resources available for rollout generation.

### Balancing exploration, tool use, and trajectory length

Exploration builds on a policy that can already follow instructions, interpret tool specifications, and use feedback. Without those capabilities, broader sampling often produces unusable attempts.

Several approaches can broaden the search: presenting the same problem through different prompts, adjusting sampling behavior, introducing controlled perturbations, and varying the available tool set. Tool variation is especially relevant when users can supply custom APIs or Model Context Protocol (MCP) tools. A model trained on a fixed tool collection needs practice interpreting unfamiliar specifications and correcting mistaken calls.

Reward tool use according to the task's needs. A required tool can justify a dedicated criterion; otherwise, rewarding calls for their own sake encourages activity without progress.

Longer trajectories give an agent more chances to inspect evidence, test alternatives, and recover. They also increase the risk of repetitive reasoning and redundant calls.

A simple token-cost is:

$$
r_{\text{effective}} = r_{\text{total}} - \lambda \cdot L
$$

Here $L$ is the rollout's token count and $\lambda$ is the cost per token in reward units. A small penalty tolerates more exploration; an excessive penalty can favor stopping before a difficult task is solved. The appropriate balance depends on the task and the model's stage of training.

Wall-clock timeouts bound individual attempts; the described practice includes 30-minute and one-hour budgets for long tasks. Frequent timeouts can reveal problems in task difficulty or policy behavior.

Evaluation should make the cost-quality tradeoff visible. Controlled token and time budgets help distinguish better decisions from the benefits of spending more resources.

### Carrying state beyond a context window

Long-running agents eventually accumulate more history than their model can process at once. Recurrent summarization compresses older material and retains a recent window verbatim:

$$
\text{context}_t = \text{summary}(\text{context}_{1:t-k}) \oplus \text{context}_{t-k+1:t}
$$

Here $\oplus$ denotes concatenation, and $k$ now refers to the recent history retained in the context. This conceptual approach, discussed in connection with ReSum, lets the agent continue after the raw history would otherwise exceed the context limit.

A second schematic version makes the summarizer explicit:

$$
\text{context}_{t} = \text{Summarizer}\!\left(\text{context}_{1:t-k}\right) \oplus \text{context}_{t-k:t}
$$

The expressions differ at their boundary: with inclusive indices, the second retains an extra position and overlaps the summarized history. An implementation must choose a consistent indexing convention.

Compression keeps the active context manageable but can discard constraints, failed approaches, or details needed later. As tasks grow longer, deciding what survives each summary becomes part of the agent's ability to complete them.

### Making experimentation faster

Research throughput matters alongside training throughput. Exploratory runs can use a cheaper configuration if it remains informative about the final setup.

One reported strategy trades a one- or two-point quality reduction for experiments that run two to three times faster. Researchers can then test more data mixtures and grader designs before checking promising changes in the stronger configuration.

The shortcut is useful only when it preserves the relative merits of candidate approaches. A faster experiment that reverses their ranking can send the research in the wrong direction. Even with a faithful proxy, small score differences need uncertainty estimates before they guide the next expensive training run.

Worker failures, network interruptions, stalled environments, and data bugs also consume compute and researcher attention. Reliable execution and useful diagnostics determine how much experimentation the available resources can support.

## 3. Extending what agents can learn and accomplish

Training changes a model's capabilities. Additional computation at inference time can change how extensively it applies those capabilities to a particular problem. Three dimensions provide a useful organizing framework:

$$
\text{Test-Time Quality} = f(\text{Deeper},\ \text{Wider},\ \text{Longer})
$$

| Dimension | How additional computation is used                       | Main challenge                                        |
| --------- | -------------------------------------------------------- | ----------------------------------------------------- |
| Deeper    | Additional sequential reasoning or recurrent computation | Turning extra computation into useful refinement      |
| Wider     | Multiple candidate solutions or parallel agents          | Producing complementary approaches and selecting well |
| Longer    | More environment interactions over a sustained task      | Preserving state and maintaining progress             |

The dimensions suggest different interventions. Recurrent computation revisits intermediate representations; parallel sampling explores several solution paths; longer trajectories allow more rounds of execution and feedback.

An illustrative expression for a favorable scaling relationship is:

$$
Q(c) \propto c^\alpha, \quad \alpha > 0
$$

Here $Q(c)$ denotes quality at inference compute budget $c$, and $\alpha$ represents a hypothetical scaling exponent. This is a conceptual model, not an established law supplied with fitted results. Bounded benchmark scores cannot follow an increasing power law indefinitely. Extra computation can yield diminishing returns or fail to help when the model repeats the same mistake.

Parallel reasoning also raises a question about the training objective. A model trained to produce one answer has no inherent incentive to make its many sampled answers complementary. Training for the eventual parallel workflow could encourage varied strategies, provided selection and coordination can recognize their value.

Longer work makes memory and recovery equally consequential. The agent must carry user constraints, tool observations, and unfinished tasks through many decisions.

### Self-improvement depends on trustworthy selection

Synthetic data and reinforcement learning suggest a recursive training process: the model generates candidate work, a filter selects useful examples, and training on those examples produces the next model.

Let $\pi_n$ be the model at generation $n$, and let $\mathcal{P}$ be the problem distribution. The data-generation step is:

$$
\mathcal{D}_{n+1} = \text{Filter}\!\left(\text{Rollout}(\pi_n, \mathcal{P})\right)
$$

The next training step is:

$$
\pi_{n+1} = \text{Train}(\pi_n,\ \mathcal{D}_{n+1})
$$

For the loop to improve performance on the target distribution, the desired condition is:

$$
\mathbb{E}_{p \sim \mathcal{P}}\!\left[r(\pi_{n+1}(p))\right] > \mathbb{E}_{p \sim \mathcal{P}}\!\left[r(\pi_n(p))\right]
$$

Improvement depends on generating useful experiences and selecting them reliably. Evaluation must continue to reflect task performance as the model becomes more familiar with its graders.

This process can reduce dependence on new human-written answers while still relying on externally designed tasks, environments, and standards. Independent verification helps when a model's judgments share the blind spots of its generated work.

A successful loop turns occasional success into consistent capability, opening harder tasks to further learning. A flawed filter can instead select convincing errors or reward exploits. Repetition alone provides no guarantee of continuing improvement.

### Bringing prediction and reward-based learning together

The distinction between learning general representations and learning useful behavior is often reflected in a staged pipeline:

$$
\text{Pre-training} \xrightarrow{\text{data handoff}} \text{Post-training (SFT + RLHF)}
$$

Pre-training typically develops broad capabilities through token prediction. Supervised fine-tuning (SFT) trains on demonstrations, while reinforcement learning from human feedback (RLHF), or other reward sources, further shapes behavior. These labels describe different objectives and workflows, but the objectives need not be confined to entirely separate phases.

The objectives make complementary contributions. Broad prediction develops a repertoire of capabilities, demonstrations show useful behavior, and reinforcement learning uses repeated attempts and feedback to make successful behavior more likely.

One proposed direction brings token prediction and reward optimization into a more integrated process:

$$
\text{Future: Next-Token Prediction + RL} \longrightarrow \text{unified training objective}
$$

A hypothetical combined objective is:

$$
\mathcal{L}_{\text{future}} = \mathcal{L}_{\text{NTP}}(\theta) - \eta \cdot \mathbb{E}_{\pi_\theta}\!\left[r(s, a)\right]
$$

The next-token-prediction loss $\mathcal{L}_{\text{NTP}}$ encourages accurate prediction, and the reward term encourages useful behavior. The coefficient $\eta$ controls their relative contribution. With $\eta = 0$, only token prediction contributes; the formal limit $\eta \to \infty$ makes the reward term dominate, assuming comparable scaling of the terms.

This proposed objective leaves substantial design choices open: scheduling, relative scales, and how the two forms of learning interact. It does not specify a replacement for existing staged pipelines.

Its motivation returns to the quality of experience. Useful tasks and trustworthy rewards can limit what additional compute teaches a model. Better environments, graders, and exploration expand those opportunities.

These training choices shape how an individual agent acts and learns. Once other agents enter the environment, their behavior becomes part of the feedback loop. An effective strategy must account for who those partners are, how they adapt, and whether they interpret a plan in compatible ways.

## 4. Learning to cooperate with other agents

Training an agent through interaction raises a further question: whose behavior is it learning to handle? A policy can become highly skilled against copies of itself while relying on conventions that unfamiliar partners do not share. The training population is therefore part of the problem. Robust competition, cooperation with people, and collaboration among language models each demand a different account of what the other participants know and how they act.

### Self-play and the minimax guarantee

Self-play creates new training challenges through repeated interaction with copies or earlier versions of an agent. The conceptual progression associated with AlphaGo—human examples, search, and further improvement through self-play—has parallels in language-model pre-training, inference-time reasoning, and learning from generated interactions. Game theory explains both the attraction of this approach and the limits of the analogy.

The clearest guarantee applies to a **finite, two-player, zero-sum game**. For strategies $\sigma_1$ and $\sigma_2$, player 1 receives expected payoff $u_1(\sigma_1, \sigma_2)$, with $u_2 = -u_1$. The minimax theorem states:

$$
\max_{\sigma_1} \min_{\sigma_2} u_1(\sigma_1, \sigma_2) = \min_{\sigma_2} \max_{\sigma_1} u_1(\sigma_1, \sigma_2) = v^*
$$

Player 1 can guarantee at least $v^*$ against any opponent, while player 2 can prevent player 1 from obtaining more than that value. These are guarantees about expected payoff across play. They allow individual losses.

Strategies may be **mixed**, assigning probabilities to choices. Making the strategy spaces explicit gives:

$$
\max_{\sigma_1 \in \Delta(\mathcal{A}_1)} \min_{\sigma_2 \in \Delta(\mathcal{A}_2)} u_1(\sigma_1, \sigma_2) = \min_{\sigma_2 \in \Delta(\mathcal{A}_2)} \max_{\sigma_1 \in \Delta(\mathcal{A}_1)} u_1(\sigma_1, \sigma_2) = v^*
$$

Here $\mathcal{A}_i$ is player $i$'s choice set, and $\Delta(\mathcal{A}_i)$ is its probability simplex. In a sequential game's normal-form representation, a choice can be a complete contingent plan. Exchanging the order of optimization over these strategies preserves the value; changing who actually moves first or what they observe can change the game.

The equilibrium value is unique even when the strategies achieving it are not. Independently computed minimax strategies remain compatible: paired together, they produce that value. Reaching this target still requires suitable learning dynamics, payoff information, and representations. Self-play alone supplies no convergence guarantee for arbitrary neural-network training. Regret minimization provides one principled route, including methods designed for large imperfect-information games.

**Exploitability** measures the vulnerability of a strategy to an informed best response:

$$
e(\sigma) = \max_{\sigma'} u_{\text{opponent}}(\sigma', \sigma) - v^*
$$

$v^*$ denotes the opponent's equilibrium value. Keeping the earlier convention that it denotes player 1's value instead gives:

```math
e(\sigma_1) = \max_{\sigma_2' \in \Delta(\mathcal{A}_2)} u_2(\sigma_2', \sigma_1) - (-v^*)
= v^* + \max_{\sigma_2'} u_2(\sigma_2', \sigma_1)
```

Here $u_2$ lists the opponent's own strategy first. Using player 1's payoff throughout makes the same shortfall explicit:

$$
e(\sigma_1) = v^* - \min_{\sigma_2'} u_1(\sigma_1, \sigma_2')
$$

Zero exploitability means the strategy delivers its minimax guarantee. In ordinary rock-paper-scissors, with payoffs of one for a win, minus one for a loss, and zero for a tie, always choosing Rock loses to always choosing Paper. Since $v^* = 0$, exploitability is $e = 0 - (-1) = 1$. A predictable sequence, such as two Rocks followed by Scissors, remains vulnerable to someone who knows the rule. Independent uniform randomization provides the robust mixture:

$$
\sigma_1^* = \sigma_2^* = \left(\frac{1}{3}, \frac{1}{3}, \frac{1}{3}\right)
$$

An opponent can know the distribution without knowing the next outcome, so no response obtains a positive expected advantage.

That robustness differs from maximizing returns against a particular population. A **population best response** can exploit predictable opponents, as an adaptive poker player does, while exposing weaknesses of its own. Perfect information does not erase this distinction: worst-case protection and performance against actual opponents remain different objectives. An agent trained against its own copies has experience with one population, which may differ substantially from its eventual users or partners.

### Hidden information makes mixtures matter

In perfect-information games such as chess and Go, the visible history identifies the current decision point. In an imperfect-information game, an **information set** $I$ groups histories that look identical to the acting player. A valid strategy uses the same action distribution throughout that set; otherwise, it would rely on unavailable information.

Rock-paper-scissors can be represented by letting one player move first while concealing the move from the second. That information restriction preserves simultaneous play's strategic structure. Revealing the first move changes it. In poker, hidden information makes the frequency of a bluff part of its value: opponents adjust their calls to the distribution they infer.

A modified rock-paper-scissors game illustrates why choosing a good mixture requires more than selecting individually attractive actions:

$$
\sigma^* = \left(P(R) = 0.4,\ P(P) = 0.4,\ P(S) = 0.2\right)
$$

One consistent payoff table leaves Rock versus Paper at one point and doubles the magnitude of contests involving Scissors:

| Row player's action | Opponent: Rock | Opponent: Paper | Opponent: Scissors |
| ------------------- | -------------: | --------------: | -----------------: |
| Rock                |              0 |              −1 |                  2 |
| Paper               |              1 |               0 |                 −2 |
| Scissors            |             −2 |               2 |                  0 |

Against the 40–40–20 equilibrium mixture, every row has expected payoff zero. Consider optimizing immediate reward:

$$
\max_{\pi_\theta} \mathbb{E}_{a \sim \pi_\theta}\left[r(s, a)\right]
$$

Every mixture achieves the same payoff against that fixed equilibrium opponent. The objective therefore cannot distinguish the particular mixture that remains robust when the opponent changes its response. Naive lookahead encounters the same ambiguity when all three actions evaluate to zero.

This explains why applying Proximal Policy Optimization (PPO) directly in self-play supplies no general minimax convergence theorem. PPO can reach equilibrium in some settings; the outcome depends on opponent selection, averaging, and the surrounding learning dynamics. Strategic learning must account for changing responses and the information available to each participant.

### Learning from accumulated regret

**Fictitious play** responds to the opponent's average strategy over past iterations. With $\bar{\sigma}_i^t$ denoting player $i$'s average after $t$ iterations:

$$
\bar{\sigma}_i^{t+1} = \frac{t \cdot \bar{\sigma}_i^t + \text{BR}(\bar{\sigma}_{-i}^t)}{t+1}
$$

The operator $\text{BR}$ returns a best response. In finite two-player zero-sum games, empirical strategies have convergence results even when individual actions keep cycling. Rates depend on the particular process and assumptions; a universal $O(1/\sqrt{T})$ rate does not apply to every fictitious-play procedure.

**Regret matching** instead compares past performance with the payoff an alternative action would have earned. Cumulative regret for action $a$ through iteration $T$ is:

$$
R^T(a) = \sum_{t=1}^{T} \left[u(a, \sigma_{-i}^t) - u(\sigma_i^t, \sigma_{-i}^t)\right]
$$

Positive regret means consistently choosing that action would have improved on the mixtures actually used. The next strategy assigns probability in proportion to positive regret:

$$
\sigma_i^{t+1}(a) \propto \max\!\left(R^t(a),\ 0\right)
$$

Normalization supplies a uniform fallback when no regret is positive:

$$
\sigma_i^{t+1}(a) = \begin{cases} \dfrac{\max(R^t(a), 0)}{\sum_{a'} \max(R^t(a'), 0)} & \text{if } \sum_{a'} \max(R^t(a'), 0) > 0 \\ \dfrac{1}{|\mathcal{A}_i|} & \text{otherwise (uniform)} \end{cases}
$$

When both players' average external regret vanishes in a two-player zero-sum game, their averaged strategies approach minimax play. Under standard bounded-payoff assumptions, an $O(\sqrt{T})$ cumulative-regret bound yields an $O(1/\sqrt{T})$ average-regret bound. The guarantee concerns the average, which can behave differently from the latest policy. Beyond zero-sum games, the solution concept also changes: Hart and Mas-Colell's original procedure establishes convergence of empirical play to correlated equilibria, rather than guaranteeing a particular Nash equilibrium for arbitrary self-play.

Weighting can give recent experience more influence. An illustrative linear weighting is:

$$
\sigma_i^T(a) \propto \max\!\left(\sum_{t=1}^{T} t \cdot \left[u(a, \sigma_{-i}^t) - u(\sigma_i^t, \sigma_{-i}^t)\right],\ 0\right)
$$

A related schematic update combines weighting with clipping stored cumulative regret to nonnegative values:

$$
R^{t+1}(a) \leftarrow \max\!\left(R^t(a) + (t+1)\left[u(a, \sigma_{-i}^t) - u(\sigma_i^t, \sigma_{-i}^t)\right],\ 0\right)
$$

Weighting observations, clipping regret, and weighting the final average strategy are distinct design choices. These expressions illustrate ingredients rather than universally defining algorithms called linear regret matching or regret matching+. Their performance depends on the complete procedure and game. Counterfactual regret minimization applies related calculations at information sets and connects local regret with overall regret, enabling equilibrium approximation in large sequential imperfect-information games.

<details><summary>The following example shows strategy construction, counterfactual evaluation, regret accumulation, and averaging:</summary>

```python
import numpy as np

ACTIONS = ['R', 'P', 'S']
PAYOFFS = np.array([[0, -1, 1], [1, 0, -1], [-1, 1, 0]])  # payoff[i][j] for player 1

def regret_matching(T=10000):
    regret = np.zeros(3)        # R^t(a) for each action
    avg_strategy = np.zeros(3)  # bar{sigma}^T

    for t in range(1, T + 1):
        # Compute strategy from regret (Formula 2)
        pos_regret = np.maximum(regret, 0)
        if pos_regret.sum() > 0:
            strategy = pos_regret / pos_regret.sum()
        else:
            strategy = np.ones(3) / 3  # uniform fallback

        # Update average strategy
        avg_strategy += strategy

        # Opponent also plays regret matching (self-play)
        opp_strategy = strategy  # symmetric game

        # Compute expected values for each action vs opponent
        ev = PAYOFFS @ opp_strategy          # u(a, sigma_{-i})
        actual_ev = strategy @ ev            # u(sigma_i, sigma_{-i})

        # Update regrets: R^{t+1}(a) = R^t(a) + [u(a, sigma_{-i}) - u(sigma_i, sigma_{-i})]
        regret += ev - actual_ev

    return avg_strategy / T  # converges to [1/3, 1/3, 1/3]
```

</details>

Multiplication by the payoff matrix computes each action's expected value; subtracting `actual_ev` gives its regret increment. The “Formula 2” comment refers to normalization of positive regret. This initialization already places both players at ordinary rock-paper-scissors' uniform equilibrium, so expected values and regrets stay zero from the first iteration. The code demonstrates the mechanics without showing convergence from an exploitable starting point. It also shares one strategy between symmetric players instead of maintaining independent learning states.

### From competition to compatible conventions

The zero-sum restriction limits what cooperation can accomplish:

$$
v_1 + v_2 = 0 \quad \text{(by definition of zero-sum)}
$$

Consequently:

$$
v_1 + v_2 = 0 \implies \Delta v_1 = -\Delta v_2
$$

Neither player's equilibrium payoff can increase without reducing the other's. In a fixed zero-sum game, adding optional, nonbinding messages—**cheap talk**—leaves each player's minimax guarantee intact: either can ignore the messages and retain its security strategy. Messages may still influence bounded or mistaken opponents. Changes to information access, commitments, or rules can also create a different strategic problem.

In general-sum games, cooperation can benefit multiple players and incompatible decisions can hurt them together. A Nash equilibrium requires that neither player gain from a unilateral deviation:

```math
u_1(\sigma_1^*, \sigma_2^*) \geq u_1(\sigma_1, \sigma_2^*) \quad \forall \sigma_1
```

```math
u_2(\sigma_1^*, \sigma_2^*) \geq u_2(\sigma_1^*, \sigma_2) \quad \forall \sigma_2
```

These inequalities need not select a unique equilibrium, and different equilibria can yield different payoffs. Strategies taken from separate equilibrium profiles may work poorly together. Adding a third player also removes the automatic applicability of the two-player minimax result, even if total payoffs stay constant.

Agents therefore face an **equilibrium-selection problem**: conventions learned within one population can clash with those learned elsewhere. Communication helps when participants can interpret each other's messages and use them to select compatible plans. Shared objectives alone do not supply that understanding.

The ultimatum game makes the role of human preferences explicit. Alice receives 100 dollars and offers Bob $x \in [0, 100]$. Acceptance gives Bob the offer and Alice the remainder; rejection gives both zero. If Bob values only his monetary payment:

$$
u_{\text{Bob}}(x, \text{accept}) = x \quad > \quad u_{\text{Bob}}(x, \text{reject}) = 0 \quad \text{for all } x > 0
$$

Backward induction suggests offering as little as Bob will accept, often summarized as:

$$
x^* \to 0^+, \quad \text{Bob accepts any } x > 0
$$

The associated expression below captures a limiting intuition but is **not a valid literal equality** for continuous positive offers:

$$
x^* = \arg\max_{x > 0}(100 - x) = \lim_{\epsilon \to 0^+} \epsilon
$$

There is no smallest positive real number, so that maximization has no attained optimum. Discrete monetary increments define a smallest positive offer; if zero is permitted, Bob's behavior when indifferent also matters. A unique Nash-equilibrium prediction requires a fuller specification of the game and its sequential rationality assumptions.

People may reject positive offers because fairness or respect affects utility. An illustrative acceptance utility is $u_{\text{human, Bob}} = x - f(100 - 2x)$, where $f$ penalizes an unfavorable imbalance. Such a model represents one possible preference, whose relevance must come from evidence about the people involved. Monetary rewards and interaction with identical copies cannot reveal unfamiliar norms on their own. Demonstrations, feedback, or explicit population knowledge supply the missing information:

$$
\text{Optimal strategy for Alice} = f(\text{human population data})
$$

Here $f$ informally represents the relationship between population evidence and strategy choice, separately from the fairness penalty. Given a distribution $\mathcal{P}$ over other players' strategies, the corresponding population best response is:

$$
\text{PBR}(\mathcal{P}) = \arg\max_{\sigma} \mathbb{E}_{\sigma_{-i} \sim \mathcal{P}}\left[u(\sigma, \sigma_{-i})\right]
$$

For human partners:

$$
\pi^* = \arg\max_\pi \mathbb{E}_{\sigma_{-i} \sim \mathcal{P}_{\text{human}}}\left[u(\pi, \sigma_{-i})\right]
$$

Performance now depends on whether the population model captures relevant preferences and habits. The utility function must also represent the desired outcome: one agent's payoff and shared welfare are separate objectives. **Imitation learning** supplies a starting point by fitting observed actions:

$$
\mathcal{L}_{\text{imit}} = -\mathbb{E}_{(s, a) \sim \mathcal{D}_{\text{human}}}\left[\log \pi_\theta(a \mid s)\right]
$$

The dataset $\mathcal{D}_{\text{human}}$ contains human actions and their states. Predicting those actions helps planning, while further strategic improvement must retain enough connection to the intended partners to remain compatible with them.

### Diplomacy connects language with strategic plans

Diplomacy combines competition and coordination among seven players who submit moves simultaneously. Another player's support can determine an action's success. The full game includes natural-language negotiation and nonbinding agreements; **no-press Diplomacy** removes the messages while retaining the coordination challenge.

DORA, trained without human demonstrations, exposed the risk of population-specific conventions: its no-press behavior could be incompatible with agents bootstrapped from human data. Strong play within one training population thus failed to ensure compatibility with another; the evidence does not require interpreting the learned policies as exact Nash equilibria.

A later approach regularized planning and reinforcement learning with a human imitation policy. In a 200-game no-press tournament involving 62 human participants, both resulting Diplodocus agents achieved higher average scores than all other participants who played more than two games. Their Elo rankings were first and third. This evaluation connects strategic improvement directly to the intended human population.

Cicero extended human-compatible play to natural-language negotiation. Two conceptual summaries highlight its ingredients:

$$
\text{Cicero} = \text{ImitationModel}(\mathcal{D}_{\text{human}}) + \text{InferenceScaling} + \text{RL with human models as environment}
$$

$$
\pi_{\text{Cicero}} = \text{RL}\!\left(\pi_{\text{imit}},\ \mathcal{E}_{\text{human-imit}}\right)
$$

These are shorthand descriptions, not complete algorithm specifications. Cicero combined a controllable dialogue model with strategic reasoning: it predicted other players' behavior from the board and conversation, refined plans while remaining anchored to those predictions, and generated and filtered messages consistent with its intentions. Treating human-like models as an “environment” abstracts this broader process. [Meta&#39;s Cicero system description](https://ai.meta.com/blog/cicero-ai-negotiates-persuades-and-cooperates-with-people/).

Across 40 games in an anonymous online league, Cicero scored more than twice the human average and ranked in the top 10% of participants who played more than one game. Those results describe the evaluated league and conditions. [FAIR Diplomacy Team, _Human-level play in the game of Diplomacy by combining language models with strategic reasoning_](https://pubmed.ncbi.nlm.nih.gov/36413172/).

The lesson extends to fully cooperative games such as Hanabi: a common score does not ensure that unfamiliar players interpret signals alike. Self-play remains useful, and compatibility need not require a newly collected human dataset in every application. What matters is how information about the intended partners enters training and planning.

## 5. Organizing work across language-model agents

Language models make it possible to exchange plans, generate independent candidates, divide investigations, and route work to specialists. These approaches spend additional inference compute in different ways and impose different coordination demands. An ensemble voting on answers needs a comparison rule; a team sharing a changing plan also needs mechanisms for keeping its decisions consistent.

The motivation is often expressed as an improving relationship between quality and compute or model generation:

$$
Q(c, t) \nearrow \text{ as } c \nearrow \text{ or } t \nearrow
$$

Here $c$ denotes inference compute and $t$ a model generation. Similarly, increasing reasoning length $L$ may improve quality:

$$
Q \approx f(L) \nearrow \text{ with } L
$$

Both expressions describe trends within an evaluated regime. More sampling can reinforce a wrong answer, newer models can regress on particular tasks, and longer reasoning can become repetitive. The system must turn additional work into better decisions.

### Agreement and verification solve different selection problems

**Consensus sampling** generates several answers and chooses the most frequent:

$$
\hat{a} = \text{mode}\left(\{a_i\}_{i=1}^N\right), \quad a_i \sim \pi(\cdot \mid q)
$$

For query $q$, the samples $a_i$ comprise $N$ attempts. Voting works most directly when answers normalize to comparable values, such as numbers or multiple-choice labels. A strict majority requires more than half the samples; a plurality needs only more votes than any individual alternative.

With independent samples of identical correctness probability $p$, a binary answer space, and ties counted as failures to select a winner, strict-majority correctness is:

$$
P(\text{consensus correct}) = P\!\left(\text{mode}\{a_i\}_{i=1}^N = a^*\right) = \sum_{k > N/2} \binom{N}{k} p^k (1-p)^{N-k}
$$

Here $a^*$ is the correct answer and $k$ counts correct samples. The equality with the mode relies on those conventions. With several wrong alternatives, the correct answer can win a plurality below 50%, so the full answer distribution matters.

| Single-attempt correctness | Number of attempts | Probability of a strictly correct majority |
| -------------------------: | -----------------: | -----------------------------------------: |
|                        60% |                 64 |                                About 93.3% |
|                        40% |                 64 |                                 About 4.0% |

Voting amplifies the sampling process's preference, including systematic mistakes. The relevant correctness probability is query-specific; average benchmark accuracy does not necessarily predict voting across heterogeneous questions. Essays and programs create an additional difficulty because different strings may express equivalent solutions. Grouping claims or extracting answers makes voting possible, but the grouping procedure becomes part of the system's reliability.

**Best-of-N** instead uses an evaluator:

$$
\hat{a} = \arg\max_{a_i \in \{a_1, \ldots, a_N\}} V(a_i)
$$

The verifier or scorer $V$ selects a candidate, allowing a correct minority answer to prevail when correctness can be recognized. If independent samples succeed with probability $p_1$, the chance of generating at least one success is:

$$
P(\text{at least one correct in N samples}) = 1 - (1 - p_1)^N
$$

With a perfect selector, that becomes the final success probability:

$$
P(\text{best-of-N correct}) = 1 - (1 - p)^N
$$

Here $p$ and $p_1$ both represent single-attempt success. At 10% per attempt, ten independent attempts have about a 65.1% chance of containing a correct answer. A verifier realizes this opportunity only if it recognizes the success and avoids preferring a failure.

<details><summary>A Boolean verifier supports a simple implementation:</summary>

```python
def best_of_n(model, query, verifier, N=10):
    """
    Sample N independent outputs and select the one that passes the verifier.

    Args:
        model: the LLM (callable: query -> response)
        query: the input problem
        verifier: function(response) -> bool (True if correct)
        N: number of samples

    Returns:
        Best verified response, or None if all fail.
    """
    candidates = [model(query) for _ in range(N)]  # N independent samples

    for candidate in candidates:
        if verifier(candidate):
            return candidate  # First verified correct answer

    return None  # All N attempts failed
```

</details>

Returning the first accepted candidate suffices for Boolean correctness; graded quality requires ranking. Independence is a requirement on `model`, not a property established by this function. Repeated deterministic calls return the same answer, whereas stochastic draws can be independent even when they use the same model and temperature. Shared model biases can still make a query consistently difficult.

The list comprehension executes sequentially in ordinary Python; concurrent sampling needs an execution mechanism. More fundamentally, a weak evaluator can reward misleading candidates. As with reinforcement learning, increasing the search budget raises both the chance of finding a strong answer and the chance of exploiting the evaluation rule.

### Parallel work and specialized routing

Autoregressive generation is sequential within a trace: later tokens depend on earlier ones. Distributing independent work can reduce elapsed time, often summarized as:

$$
\text{Latency} = O(L / \text{parallelism})
$$

For a trace containing $L$ tokens at speed $s$ tokens per second:

$$
\text{Latency}_{\text{serial}} = \frac{L}{s}
$$

If $K$ independent workers each handle a useful share of $L/K$ tokens, ideal latency becomes:

$$
\text{Latency}_{\text{parallel}} = \frac{L/K}{s} = \frac{L}{Ks} = \frac{\text{Latency}_{\text{serial}}}{K}
$$

This calculation assumes sufficient hardware, balanced workloads, comparable speeds, and negligible startup, communication, and aggregation costs. It holds generated tokens constant, although prompts and repeated context processing also consume compute. It supplies no guarantee of equal quality: sixty one-minute attempts cannot generally replace an hour of reasoning whose later steps depend on earlier discoveries.

Anthropic's June 2025 account of its multi-agent research system described benefits for investigations with several independent directions, alongside higher token use and difficulties with substantial shared context or dependencies. The gains followed the workload's structure. [Anthropic, _How we built our multi-agent research system_](https://www.anthropic.com/engineering/multi-agent-research-system).

Routing offers another way to use complementary capabilities. A calculator can handle exact arithmetic; an image-capable model can interpret visual input; a specialist can handle tasks where evaluation demonstrates an advantage. The conceptual choice is:

$$
\pi_{\text{router}}(q) \to \text{model}_k, \quad k = \arg\max_k \text{quality}(\text{model}_k, q)
$$

Because quality is unknown before execution, practical routing estimates performance:

$$
\pi_{\text{router}}(q) = \arg\max_{k \in \{1, \ldots, M\}} \mathbb{E}\left[Q(\text{model}_k, q)\right]
$$

Among $M$ models, the router chooses the index with the best expected quality for query $q$. Cost and latency may also influence the decision, although these expressions omit them. Effective routing can require little inter-agent conversation, but its estimates must survive actual use: a query may conceal a difficult subproblem, fall outside a specialist's experience, or require several capabilities together.

### Keeping shared decisions consistent

Dividing work introduces dependencies as well as opportunities. In a software task, two agents can each make a reasonable local design choice and still produce incompatible results. Fluent communication helps only when it carries the assumptions and decisions that affect the other agent's work.

Reliable collaboration therefore needs shared state that preserves relevant constraints and evidence, clear responsibilities that prevent gaps and duplication, and a way to propagate changes in assumptions. Agents must resolve disagreements by comparing evidence, detect stalled or invalid work, and evaluate the combined result for errors introduced during synthesis. Better individual models help, but the collective outcome still depends on how their decisions fit together. These requirements become especially consequential when the team's output is a scientific proposal that must survive verification beyond the conversation.

## 6. Putting agents to work in scientific discovery

Scientific discovery brings the demands of training and cooperation into one workflow. A model may predict a protein structure, but research also requires choosing a question, preparing inputs, interpreting results, and deciding what evidence supports a claim. Agents can connect these activities through scientific software, literature, and persistent memory. The Virtual Lab and the related Agent School approach illustrate how teams acquire knowledge, organize work, and connect computational proposals to experiments.

Related projects address other parts of the research process. **Paper2Agent** makes published methods accessible through reusable software interfaces, while **Agents4Science** examines substantial AI participation in scientific authorship and review. The Virtual Lab provides a concrete example of how agent coordination can lead to experimental evaluation.

### From individual predictions to coordinated research

The intended scope of a scientific agent extends across the research process:

$$
\text{Hypothesis Generation} \longrightarrow \text{Experimental Design} \longrightarrow \text{Tool Invocation} \longrightarrow \text{Data Analysis} \longrightarrow \text{Manuscript Preparation}
$$

The arrows describe a workflow that can loop back: an unsuccessful analysis may change the hypothesis, and an experiment may expose a missing assumption. Agents need a record of earlier decisions to revise that workflow coherently. Its automation also depends on the domain. Software can execute many computational analyses, while protein production, biological assays, and materials experiments still require physical infrastructure and experimental collaborators. Manuscript generation alone cannot establish that those validation steps occurred.

The **Virtual Lab** organizes this work around a Principal Investigator, or **PI**, agent. A human supplies the objective and constraints; the PI coordinates specialists, assigns work, and integrates findings. Domain specialists contribute perspectives such as biology and immunology, a machine-learning specialist implements computational methods, and a scientific critic examines assumptions and evidence. Humans review decisions and connect the computational work to experiments. [Swanson et al., _The Virtual Lab of AI agents designs new SARS-CoV-2 nanobodies_](https://www.nature.com/articles/s41586-025-09442-9).

A conceptual representation of the laboratory is:

$$
\mathcal{M} = \left( \mathcal{A}, \mathcal{G}, \mathcal{S}, \mathcal{T}, \mathcal{R} \right)
$$

Here $\mathcal{A} = \{a_{\text{PI}}, a_{\text{bio}}, a_{\text{ML}}, a_{\text{imm}}, a_{\text{critic}}\}$ is an example team, $\mathcal{G}$ specifies communication, $\mathcal{S}$ represents notebook memory, $\mathcal{T}$ contains tools, and $\mathcal{R}$ records resource constraints. This notation describes components rather than formally specifying the published implementation.

Meeting transcripts, intermediate outputs, and unresolved questions help the PI maintain a shared account of the project. A computational sandbox supports code execution and revision. Human feedback supplies missing context when the team begins pursuing an unhelpful direction.

### Comparing plans while preserving critical judgment

Parallel meetings let agents explore several approaches to an agenda. Represent meeting $k$ as a transcript:

$$
T^{(k)} = \left( u_1^{(k)}, u_2^{(k)}, \ldots, u_{N_k}^{(k)} \right), \quad k \in \{1, \dots, K\}
$$

Each $u_j^{(k)}$ is an utterance, and $N_k$ is the transcript's length. The PI can combine useful elements from the resulting plans. An illustrative aggregation objective is:

$$
\bar{P} = \arg\max_{P} \sum_{k=1}^K \text{Sim}\left( P, \text{Summary}(T^{(k)}) \right) - \lambda \cdot \text{Risk}(P \mid a_{\text{critic}})
$$

This balances agreement with meeting summaries against a critic-informed risk assessment. Its similarity and risk functions illustrate plan selection; they are not reported quantitative components of the published system.

Agreement across discussions can reveal a stable plan, but it supplies no independent experimental evidence. Similar models may share mistaken premises, and rewarding similarity may suppress an unusual, valuable idea. The critic therefore needs to examine the reasons behind a proposal. Meeting order, access to information, and the timing of critique also deserve controlled evaluation: their value rests on improvements in the resulting research, rather than the amount of discussion they produce.

### Developing and evaluating specialist knowledge

**Agent School** approach connects these organizational roles to training. A human specifies topics; agents generate questions, retrieve and study references, and answer quizzes prepared by teacher agents. The account includes supervised fine-tuning as a route to specialization.

This distinction matters because a role name does not establish expertise. Prompting an agent to act as an immunologist changes its instructions; retrieval changes its context; fine-tuning changes its weights. Evaluations should identify which mechanism produced the claimed specialization.

A next-token training objective over specialized material is:

$$
\mathcal{L}_{\text{SFT}}(\theta) = -\frac{1}{|\mathcal{D}_{\text{spec}}|} \sum_{X \in \mathcal{D}_{\text{spec}}} \sum_{t=1}^{|X|} \log P_\theta\left( x_t \mid x_{<t} \right)
$$

The dataset $\mathcal{D}_{\text{spec}}$ contains training sequences $X$, and $\theta$ denotes the model parameters. A shorthand for the gradient update and intended differentiation of specialists is:

$$
\theta^{(s+1)} = \theta^{(s)} - \eta \nabla_\theta \mathcal{L}_{\text{SFT}}\left(\theta^{(s)}\right) \implies \|\theta_{\text{bio}} - \theta_{\text{ML}}\|_2 > 0
$$

The learning rate is $\eta$. The implication expresses an intended effect, not a theorem: the update alone guarantees neither different parameter vectors nor different capabilities. Parameter separation also does not measure expertise or demonstrate that catastrophic forgetting has been avoided.

Likewise, a graduation threshold such as $\tau_{\text{grad}}$ is only as useful as the examination. Quizzes should test relevant knowledge and tool use, while evaluation on new research tasks should establish whether learning transfers beyond familiar material. Teacher agents can make mistakes, so their examinations also require validation.

### Connecting nanobody design to experiment

The Virtual Lab's protein-design study puts this coordination into practice. Agents assembled a workflow combining the protein language model ESM, AlphaFold-Multimer for complex-structure prediction, and Rosetta for structural refinement and scoring. The project produced 92 nanobody designs for experimental evaluation. The published report highlights two designs with improved binding to JN.1 or KP.3 variants while retaining binding to the ancestral spike protein. [Virtual Lab study](https://www.nature.com/articles/s41586-025-09442-9).

Nanobodies are compact antibody-derived binding domains. Even their relatively short sequences imply an enormous theoretical search space: a length-L sequence over 20 amino acids has $20^L$ combinations. For $L=120$, $20^{120}$ is approximately $1.3 \times 10^{156}$. The study explored modifications of existing nanobody sequences, without enumerating this space.

The workflow progressively prioritizes candidates:

```
Research objective and experimental constraints
                      ↓
Candidate sequence modifications
                      ↓
ESM sequence scoring
                      ↓
AlphaFold-Multimer complex predictions
                      ↓
Rosetta structural refinement and scoring
                      ↓
Candidate ranking and iterative selection
                      ↓
92 designs selected for experimental evaluation
                      ↓
Protein production and binding measurements
                      ↓
Evidence for follow-up experiments
```

Each computational stage offers a different signal: sequence plausibility, a possible structure and its confidence, or the score of a modeled configuration. Combining them can support candidate ranking, but experimental binding measurements remain necessary to evaluate the proposed binders.

### Interpreting computational scores

An illustrative score combines sequence plausibility with penalties for undesirable motifs:

$$
\mathcal{S}_{\text{ESM}}(x) = \frac{1}{L} \sum_{i=1}^L \log P_\phi(x_i \mid x_{\setminus i}) - \lambda \sum_{k=1}^K \mathbb{I}(m_k \subset x)
$$

The first term averages conditional log probabilities across positions. The second penalizes motifs $m_k$, using indicator $\mathbb{I}$ and weight $\lambda$; here $K$ counts motifs. This conceptual example does not reproduce the study's implemented ESM score or establish that its pipeline used those penalties. Sequence likelihood remains a model-derived signal rather than a measurement of protein stability.

A corresponding energy-difference expression is:

$$
\Delta G_{\text{bind}} = E_{\text{Rosetta}}(\text{Complex}) - \left[ E_{\text{Rosetta}}(\text{Nanobody}) + E_{\text{Rosetta}}(\text{Target}) \right]
$$

Despite the notation $\Delta G$, subtracting Rosetta scores does not automatically produce a calibrated thermodynamic binding free energy. Interpreting Rosetta energy units as physical units requires an appropriate mapping. Structural relaxation likewise should not be equated with a full molecular-dynamics simulation.

Confidence thresholds and energy cutoffs depend on the protocol and its validation. These explanatory expressions cannot establish universal selection rules or measured affinities.

### Keeping experimental claims within the evidence

Binding measurements introduce their own interpretive assumptions. A saturation curve can be represented by a Hill-type equation:

$$
Y([L]) = Y_{\max} \frac{[L]^h}{K_d^h + [L]^h} + Y_{\text{background}}
$$

Here $[L]$ denotes concentration, $Y$ the measured response, $Y_{\max}$ its amplitude above background, and $h$ a shape parameter. Under appropriate assumptions for simple equilibrium binding, the midpoint can represent a dissociation constant. More general response curves need not yield a direct thermodynamic $K_d$.

The study reports ELISA binding measurements, which support binding claims under the tested conditions. They do not independently establish nanomolar equilibrium affinity, neutralization, or clinical efficacy. A flat curve indicates no detectable response within the assay range; it does not justify assigning $K_d \to \infty$ to every earlier human-designed binder. Limited binding to unrelated proteins can inform specificity assessment while leaving broader off-target effects and toxicity unresolved.

The achievement is the connection between coordinated computation and experimental follow-through: agents implemented a design process, selected a manageable batch, and experimental collaborators tested the candidates. The 92 designs constituted an evaluation batch, with further work needed to establish therapeutic value. For scientific agents, reliable progress therefore requires a traceable path from the research question through computational decisions to the measurements that support each claim.

## 7. Distinguishing agent progress from evaluation noise

Experimental follow-through makes a scientific proposal testable. A claim that one agent is more reliable than another raises an additional question: would the advantage persist across other relevant tasks and repeated runs? The same issue applies when comparing an RL update, a new training mixture, or a multi-agent workflow. A three-percentage-point improvement has different evidential weight on a small collection of tasks and on a large, well-designed evaluation.

### Task complexity and statistical evidence

An expensive software-repair trajectory can involve thousands of decisions yet contribute only one pass-or-fail observation. HumanEval contains 164 problems; SWE-bench Lite and SWE-bench Verified contain 300 and 500 tasks respectively. These counts describe particular benchmark versions. Rich tasks measure capabilities that simpler questions may miss, but their complexity does not automatically provide enough observations to distinguish nearby systems. [SWE-bench benchmark descriptions](https://www.swebench.com/).

Long tasks can amplify changes in step reliability. If success requires every step to be correct, with a constant conditional error probability $\epsilon$ over $L$ required steps:

$$
P(\text{solve}) = (1 - \epsilon)^L
$$

At $\epsilon = 0.05$, success is approximately 77% over five steps and 13% over 40. Actual agents can recover from mistakes, encounter steps of different difficulty, and take different routes. The expression therefore illustrates error accumulation under specific assumptions; trajectory length alone does not establish a benchmark's ability to discriminate between models.

Statistical interpretation begins by identifying the target. Under a **super-population framework**, benchmark questions are a sample from a larger population of relevant tasks, and the score estimates expected performance on that population. Question selection then creates uncertainty even for deterministic models. If the claim concerns only the exact published questions, that source of uncertainty is outside the narrower target.

### Measuring uncertainty with paired results

Let $A(x_i) \in \{0, 1\}$ record whether model A solves question $x_i$. For $n$ independent, equally weighted questions, observed accuracy and a common plug-in estimate of its standard error are:

$$
\bar{A} = \frac{1}{n} \sum_{i=1}^n A(x_i), \quad \text{SEM}(\bar{A}) = \sqrt{\frac{\bar{A}(1 - \bar{A})}{n}} \leq \frac{1}{2\sqrt{n}}
$$

The bound follows from Bernoulli variance being at most $1/4$. Standard error measures variability in the estimated mean across repeated samples; a normal-approximation 95% confidence interval has a half-width of about 1.96 standard errors. At $n=164$ and accuracy near 50%, these are approximately 3.9 and 7.65 percentage points respectively. At observed accuracy zero or one, the plug-in estimate's zero value does not establish certainty about population performance. Related questions can reduce the effective sample size, and narrow task coverage remains a limitation even with precise scores.

Comparisons should preserve **pairing**: run both systems on the same questions and analyze $D(x_i) = A(x_i) - B(x_i) \in \{-1, 0, +1\}$. For independent questions:

$$
\text{Var}(\bar{D}) = \frac{\text{Var}(A(x) - B(x))}{n}
$$

The item-level difference has variance:

$$
\text{Var}(A - B) = \sigma_A^2 + \sigma_B^2 - 2 \rho_{AB} \sigma_A \sigma_B
$$

Here $\rho_{AB}$ measures correlation between the models' outcomes. Shared successes and failures cancel in the difference, so positive correlation improves precision. Aggregate scores alone discard that information. In practice, align results by question identifier, subtract the scores, and estimate the mean difference's standard error from the sample variance of those differences. Equal array lengths do not verify alignment.

Under suitable sampling assumptions and an adequate normal approximation, the standardized difference is:

$$
z = \frac{\bar{A} - \bar{B}}{\text{SEM}_{\bar{A}-\bar{B}}}
$$

A conventional two-sided 5% test rejects equal population means when $|z|>1.96$. Failure to reject does not establish equality, and a p-value is not the probability that the null hypothesis is true. Report the effect and its uncertainty together. Very few discordant binary outcomes can make an exact paired test preferable; a zero estimated variance needs explicit handling rather than an automatic conclusion of no difference.

For models with similar outcome variance $\sigma^2$ and correlation $\rho$:

$$
\text{SE}(\bar{A} - \bar{B}) = \sqrt{\frac{2(1 - \rho)}{n}} \sigma
$$

When $\rho=0.5$, this equals $\sigma/\sqrt{n}$, the standard error of a **single model's mean**. An unpaired difference between two independent means with equal variance has a larger standard error by a factor of $\sqrt{2}$. The correlation of one-half is an illustrative approximation; direct paired results determine the uncertainty for the models actually being compared.

### Separating question noise from generation noise

**Question-selection noise** reflects which tasks enter an evaluation. **Sampling noise**, also called prediction noise, reflects the different outputs a stochastic system can produce on the same task. Their remedies differ.

Let $A(x, \epsilon)$ denote correctness on question $x$ under generation randomness $\epsilon$; here $\epsilon$ represents a run's randomness, separately from the earlier step-error probability. For one random score, the law of total variance gives:

$$
\text{Var}(\hat{A}) = \underbrace{\text{Var}_x[\mathbb{E}_\epsilon[A(x, \epsilon)]]}_{\sigma^2_{\text{question}}} + \underbrace{\mathbb{E}_x[\text{Var}_\epsilon[A(x, \epsilon)]]}_{\sigma^2_{\text{sampling}}}
$$

In this identity, $\hat{A}$ denotes a single score. For the average over $n$ independent questions and $m$ conditionally independent draws per question:

$$
\text{SEM}_{\text{total}}^2 = \frac{\sigma^2_{\text{question}}}{n} + \frac{\sigma^2_{\text{sampling}}}{nm}
$$

More questions reduce both terms. More draws per question reduce the sampling term while leaving any positive question-selection component. Repeated runs can estimate the solve probabilities of the chosen questions precisely without making those questions more representative.

For a paired comparison, apply the decomposition to the difference between systems. Models with similar expected performance on each question can have a small question component in their difference. Empirical work reports that paired prediction noise often exceeds paired data noise, so averaging can substantially improve such comparisons. The relative importance of the two components must be assessed for the actual evaluation. [Sida Wang, _Measuring all the noises of LLM Evals_](https://arxiv.org/abs/2512.21326).

This distinction also clarifies the earlier discussion of pass@k and best-of-N. **Averaging** repeated correctness scores estimates expected single-attempt accuracy more precisely. **Selecting** the best output changes the evaluated system and can improve its expected success rate, subject to the selector's reliability. Reports need to distinguish those uses of additional inference compute. Repeated outputs remain grouped by question; treating all $nm$ runs as unrelated tasks can underestimate uncertainty. Paired resampling must preserve those groups.

### Why some noise patterns are predictable

A beta distribution provides a compact model of how solve probabilities vary across questions:

$$
P \sim \text{Beta}(\alpha, \beta), \quad f(p) = \frac{1}{\text{B}(\alpha, \beta)} p^{\alpha - 1} (1 - p)^{\beta - 1}
$$

The positive parameters $\alpha$ and $\beta$ determine shape, $\text{B}(\alpha, \beta)$ normalizes the density, and the mean is $\mu=\alpha/(\alpha+\beta)$. When both parameters are below one, the distribution is U-shaped: many questions have solve probabilities near zero or one, with fewer in the middle.

To explain correlation between two models, an additional joint assumption is needed: they share a latent item probability $P$, and their binary outcomes are independent conditional on it. If $\alpha+\beta=1$:

$$
\text{Var}(P) = \frac{\mu(1 - \mu)}{\alpha + \beta + 1} = \frac{\mu(1 - \mu)}{2}
$$

Under those assumptions, the covariance of their outcomes equals $\text{Var}(P)$, giving:

$$
\rho = \frac{\text{Cov}(A_i, B_i)}{\mu(1 - \mu)} = \frac{0.5 \mu(1 - \mu)}{\mu(1 - \mu)} = 0.5
$$

This explains how the one-half correlation used above can arise. A beta fit to each model's individual difficulty distribution alone does not establish the shared-probability assumption. Specialization and other shared failure modes can change the relationship. A continuous beta distribution also has no point mass at zero; genuinely unsolvable questions and multiple-choice guessing floors require additional treatment. Observing no successes in finitely many runs does not prove impossibility.

Predictable noise patterns can support approximate error estimates when item-level results are unavailable. Their practical value depends on empirical validation; observed paired covariance supplies more direct evidence when it is available.

### Auditing the questions behind the score

Question-level results also connect statistical evaluation to the earlier problem of grader quality. A **doubly sorted heatmap** places questions in rows and models in columns, ordered by average difficulty and overall performance. Correctness or estimated solve probabilities reveal shared failure patterns and ranking reversals. Those reversals can reflect specialization, generation randomness, or grading defects; a stronger average score does not imply solving every question that a weaker model solves.

One diagnostic is the **point-biserial correlation** between an item's binary outcome across models and their overall scores:

$$
r_{\text{pbis}, i} = \text{Corr}(X_i, \bar{X}) = \frac{\bar{Y}_1 - \bar{Y}_0}{s_Y} \sqrt{p_i (1 - p_i)}
$$

Here $X_i$ records correctness on item $i$, $p_i$ is the fraction of models solving it, $\bar{Y}_1$ and $\bar{Y}_0$ are the mean overall scores of models that pass and fail, and $s_Y$ is the standard deviation of those overall scores, using consistent population-moment normalization. A negative value means the models passing the item score lower overall on average, making the item useful to inspect. Excluding the item itself from the overall score avoids mechanically including its own contribution.

Repeatedly reproducing distinctive wrong benchmark answers can also suggest contamination. It does not establish exposure on its own: shared sources, ambiguity, and coincident mistakes provide alternative explanations. These patterns help prioritize checks of prompts, reference answers, tests, and dataset provenance. For agent training, that audit closes the loop between what the benchmark rewards and the behavior developers actually want.

### Designing evaluations to detect useful gains

Evaluation size should follow the improvements a comparison needs to resolve. For a target accuracy difference $\Delta p$, the signal-to-noise ratio is:

$$
\text{SNR} = \frac{\Delta p}{\text{SE}_{\text{paired}}} \approx \frac{\Delta p \sqrt{n}}{\sigma}
$$

The approximation uses the earlier equal-variance, one-half-correlation relationship. Suppose the target gain is 2.5 percentage points and $\sigma=0.5$. These are illustrative assumptions, not universal consequences of increasing model size or compute. Placing the expected effect 1.96 standard errors from zero requires:

$$
n \geq \left(\frac{0.98}{\Delta p}\right)^2 \approx \mathbf{1,537} \text{ questions}
$$

The following calculations use those same assumptions; standard errors and margins are in percentage points.

| Evaluation size                     | Questions | Approximate paired SE | 1.96 × SE | SNR for a 2.5-point gain |
| ----------------------------------- | --------: | --------------------: | --------: | -----------------------: |
| HumanEval                           |       164 |                  3.90 |      7.65 |                     0.64 |
| SWE-bench Lite                      |       300 |                  2.89 |      5.66 |                     0.87 |
| SWE-bench Verified                  |       500 |                  2.24 |      4.38 |                     1.12 |
| CRUXEval                            |       800 |                  1.77 |      3.46 |                     1.41 |
| Illustrative significance threshold |     1,537 |                  1.28 |      2.50 |                     1.96 |
| Illustrative larger evaluation      |    10,000 |                  0.50 |      0.98 |                     5.00 |

The named sizes refer to the benchmark versions discussed above; CRUXEval contains 800 functions. The statistical columns are calculations under the stated assumptions, rather than empirical error estimates for particular submissions. [CRUXEval benchmark description](https://crux-eval.github.io/).

The 1,537-question threshold places the expected standardized effect at the rejection boundary. It does not provide a high probability of detecting that effect. **Statistical power** is the probability of rejecting the null when the specified improvement is real. Under the same fixed-variance normal approximation, a two-sided 5% test needs roughly 3,140 independent questions for 80% power to detect a 2.5-point gain. Lower paired variance, more repeated sampling, stronger correlation, or a larger effect can reduce the required size; clustering or smaller effects can increase it.

A useful report therefore identifies the benchmark version, task count, attempts per task, sampling and selection rules, resource budget, observed difference, and an uncertainty estimate appropriate to the design. Retaining item-level results supports both paired analysis and later audits. For RL experiments and multi-agent systems, these details establish whether an apparent improvement reflects better decisions, additional inference compute, or uncertainty in the measurement. Scientific-agent comparisons need the same clarity about the population of research tasks to which their results are meant to apply.

## Building a dependable path from action to evidence

An agent's reliability depends on the quality of the feedback that shapes its next decision. In training, that feedback comes from tasks, environments, and graders. In a team, it also comes from partners whose knowledge, conventions, and assumptions must be understood. In scientific research, computational judgments ultimately meet measurements that can support or overturn them. Statistical evaluation makes the uncertainty of broader performance claims explicit and helps expose defects in the measurements themselves.

The same questions recur at each scale. Does the task produce useful experience? Can the evaluator recognize a good result? Does the agent preserve the information needed for its next action? Can collaborators combine their work without losing constraints or introducing contradictions? Is the measured gain large enough relative to its uncertainty to support the intended claim? More computation is valuable when it improves these answers.

The coding patch and the proposed nanobody thus share a practical requirement: a traceable connection between what the system was asked to accomplish, the decisions it made, and the evidence that the result works. Establishing broader progress also requires stating which tasks that evidence covers and how precisely performance has been measured. Improving that connection gives training, multi-agent coordination, scientific automation, and evaluation a common direction.
